# CLAUDE.md

## Project Overview

Streamlit application for clinical transcription using Deepgram's Nova-3 Medical model, with Nova-3 Pharma (drug names) selectable per run.

A Streamlit-free core (`nova/`) is consumed **in-process** by the Streamlit UI (`streamlit_app.py`): it builds options, runs batches, parses responses, decides who may sign in, and writes the PHI-free audit trail, keeping that logic framework-free and unit-testable independent of the UI.

## Commands

```bash
uv sync                                                          # Install dependencies
uv run streamlit run streamlit_app.py                           # Run the Streamlit UI
uv run ruff check .                                              # Lint
uv run ruff format .                                            # Format
uv run ty check .                                               # Type check
uv run pytest                                                    # Test
uv run python scripts/live_check.py                              # Live API check (billed; needs DEEPGRAM_API_KEY)
uv run python scripts/synthetic_eval.py [runs]                   # Model comparison on TTS audio (billed)
uv run python scripts/calibrate.py path/to/folder                # Threshold calibration on de-identified audio (billed)
```

When working with Python, invoke the relevant `/astral:<skill>` for uv, ty, and ruff to ensure best practices are followed.

## Claude Code hooks

`.claude/settings.json` (tracked/shared) wires **two** scripts in `.claude/hooks/`, each launched via `bash` with `$CLAUDE_PROJECT_DIR` so they use the project's pinned tools; **personal overrides belong in `.claude/settings.local.json` (gitignored)**. Newly added or changed hooks require review before they fire (run `/hooks`, or restart the session). Both are covered by `tests/test_hooks.py`.

The two have **deliberately opposite failure modes**, and the asymmetry is the design: a *security guard* that cannot do its job must refuse, while a *quality gate* that cannot do its job must stand aside — a blocking Stop hook unable to read its own loop guard would wedge the session.

- **`block-secrets.sh`** (PreToolUse `Edit|Write|MultiEdit`) — denies edits to `.env` / `.env.*` / `secrets.toml` / `.secrets.toml` / `.envrc` / `.envrc.*` **case-insensitively** (so `.ENV` can't slip past on a case-insensitive filesystem) with exit 2, leaving the tracked templates `.env.example` and `.streamlit/secrets.toml.example` editable. The sign-in template's name is load-bearing: `example.secrets.toml` would match `*.secrets.toml` and be blocked, while `secrets.toml.example` matches no pattern — nor `.gitignore`'s exact-basename `secrets.toml`, nor the `Read(./**/secrets.toml)` deny rule — so it stays tracked, readable, and editable (`tests/test_hooks.py` pins both names). **Fails closed** (exit 2) on *both* unreadable-event paths — `jq` missing, and event JSON that `jq` cannot parse — rather than silently allowing the edit. Note `.envrc.*` is explicit: `*.env.*` requires a literal `.env.` substring, so `.envrc.local` (direnv's `source_env_if_exists` target) once walked straight through, and `.gitignore` carries the matching entry.
- **`gates.sh`** (Stop) — runs the four project gates **whole-project** when a turn finishes: `ruff format .` (which **applies**, so CI's `--check` never fires), then `ruff check .`, `ty check .`, and `pytest -q` (which only **report**). Blocks the stop (exit 2) with each failing gate's output truncated *individually*, so a long pytest failure cannot push the ruff/ty findings out of the message. A `stop_hook_active` guard prevents an infinite fix-loop — note it blocks **exactly once per stop chain**: the retry short-circuits without re-running, so a claimed fix is not re-verified by the hook.

**Why whole-project, and why not PostToolUse.** A former `py-checks.sh` ran `ruff`/`ty` per edit against the **single edited file**. That is blind in the way that matters here: `streamlit_app.py` re-imports ~15 names from `nova/` under aliased underscore names, so changing a `nova/` signature type-checks clean on its own file while the caller it just broke is never examined — the gate reports PASS on exactly the change most worth catching. Its `ruff check --fix` was worse: it silently rewrote files mid-turn (deleting imports written before the body that uses them) and exited 0 with empty stderr, leaving Claude's in-memory copy stale. Running the gates at the **turn boundary** fixes both — nothing mutates while Claude is still authoring, and cross-file regressions are actually seen — at a cost of ~3.2s per turn (warm; `pytest -q` is ~2.9s of it, most of that the four subprocess-based tests — the AppTest smoke run alone is ~1s).

## Continuous integration

`.github/workflows/ci.yml` (GitHub Actions) runs the **same four gates the hooks enforce locally** — `ruff format --check`, `ruff check`, `ty check`, `pytest` — plus `uv sync --locked` (fails on lockfile drift), across a **Python 3.12 + 3.13 matrix** (`fail-fast: false`) on push to `main`, every pull request, `workflow_call` (so `release.yml` can gate on it), and manual `workflow_dispatch`. Installs via `astral-sh/setup-uv` (cached). **Needs no secrets**: tests mock `DeepgramClient`, so CI never makes a real API call (upholds the PHI policy). Hardening: least-privilege (`permissions: contents: read`), both actions **SHA-pinned** (with `# vX.Y.Z` comments, kept fresh by `.github/dependabot.yml`), `persist-credentials: false` on checkout, a job `timeout-minutes: 10`, and a `concurrency` group that cancels superseded runs.

**The job id and the matrix values are a branch-protection contract, and this is the repo's highest-consequence silent-failure mode.** GitHub names an unnamed matrix job's check runs `<job-id> (<matrix value>)`, so `checks:` + `["3.12", "3.13"]` are the *sole* source of the `checks (3.12)` / `checks (3.13)` contexts the `main` ruleset requires. Rename the job, add a `name:` to it, drop a leg, or add a **second matrix dimension** (an `os:` leg renames every context to `checks (ubuntu-latest, 3.12)` — `tests/test_ci_workflow.py` asserts `set(matrix) == {"python-version"}` for exactly this reason), and a required context is never reported again — GitHub holds it **pending forever**, every PR becomes unmergeable, and `gh pr merge --auto` waits on something that will never arrive, with **no error surfaced anywhere**. Change the ruleset first. The matrix is also the only interpreter pin (there is no `.python-version`), so it is what verifies the `requires-python = ">=3.12"` floor. Everything in the file is load-bearing for a reason of this kind; a four-lens audit found nothing removable, so treat "tidying" it as a change to repo settings, not to YAML.

The workflow is itself guarded by `tests/test_ci_workflow.py`, which **parses it with PyYAML** and asserts structural invariants (gates run in real `run:` steps, the job id / matrix values / `fail-fast: false` are pinned, `workflow_call` stays available, every `uses:` is SHA-pinned, no `write` permission scope, `pull_request` not `pull_request_target`, no untrusted `github.event.*`/`head_ref`/`inputs.*` interpolation in a `run:` step).

## Release automation

`.github/workflows/release.yml` (GitHub Actions) cuts releases from a **version bump**, not a hand-pushed tag. Bump `[project].version` in `pyproject.toml` (keep it **static** and plain `X.Y.Z` — a `dynamic = ["version"]` would drift from the tag, and no `[tool.poetry]` table) and land it on `main`; the workflow reads the declared version, and if `vX.Y.Z` is not tagged yet it gates on CI, creates the tag, and publishes the Release with `--generate-notes`.

**One workflow does both halves, and that is the whole design.** GitHub will not start a workflow run from a ref created by the default `GITHUB_TOKEN` (the recursive-workflow guard), and **the guard is keyed on the token, not the transport** — a `POST /git/refs` is suppressed exactly as a `git push` would be. So the obvious split ("workflow A pushes the tag, workflow B fires on it") cannot work without minting a PAT or App token, in a repo that advertises needing no secrets. Doing both in one run needs no second identity, and the guard then works *for* the design: the tag this run creates cannot start a second run, which is what makes keeping the `v*` escape hatch safe from double-releasing. **The same rule runs forward**: the `release: published` event this run emits will not start an `on: release` workflow either, so anything that must happen on a release (a PyPI publish, say) belongs in the `release` job as another step — wired as its own workflow it would silently never run.

Three jobs: **`resolve`** (parses the version with stdlib `tomllib` — a grep would catch `requires-python` — validates it as a plain `X.Y.Z` before it becomes a git ref *and* a `$GITHUB_OUTPUT` line, and probes `GET /git/ref/tags/{tag}`, the **exact-match** endpoint; the older plural `git/refs/` prefix-matches, so `v0.1` would "find" `v0.10.0`); **`gate`** (`uses: ./.github/workflows/ci.yml`, skipped when there is nothing to release so an ordinary push does not run CI twice); **`release`** (creates the tag via an atomic `POST /git/refs` — `create || confirm-it-exists-now`, never a `PATCH`, so it can create a tag but never move one — then `gh release create … --generate-notes --verify-tag`). On the `v*` escape hatch, `resolve` additionally **refuses a pushed tag that disagrees with the declared version** (`exit 1`), so hand-tagging `v0.9.0` on a 0.8.1 tree stops there instead of publishing a Release that lies.

**Detection is level-triggered, never a diff**: it asks "is the declared version tagged yet?", not "did this push change it?". That is why there is no `paths:` filter — the property being bought is self-healing, so an evicted or half-dead run recovers on the next push. It also avoids `github.event.before` (all-zeros on a first push, dangling after a force-push) and `HEAD~1` (misses a bump that is not in the tip commit of a multi-commit push).

The **CI gate is not belt-and-braces**: the `main` ruleset requires `checks (3.12)`/`checks (3.13)` but does **not** require a pull request, and carries an always-bypass actor — so a direct push to `main` can skip CI, and the gate is the only thing between a red commit and a published Release. Do **not** add the reusable-call check runs to branch protection: they never run on `pull_request`, so every PR would hang and take the Dependabot `--auto` queue with it.

Least-privilege: top-level `contents: read` with `contents: write` confined to the single publishing job, and pointedly **no `pull-requests` scope** (it opens no PRs, so it can never hit the "GitHub Actions is not permitted to create or approve pull requests" policy); `concurrency` uses a constant group with `cancel-in-progress: false` (never abort a mid-publish run, and serialize a main push against a hand-pushed tag). Guarded by `tests/test_release_workflow.py`, whose `test_no_secrets_are_used` / `test_every_gh_token_is_the_default_token` are what keep the recursion reasoning above true.

**Known limits, stated rather than hidden.** A constant concurrency group keeps only one *pending* run, so three rapid pushes evict the middle one — detection self-heals on the next push, but bump one version per PR. Reverting to an already-released version does nothing; rollback means a forward bump. A hand-made **draft** Release for the target tag makes the publish step fail loudly rather than stomp it.

## Dependabot auto-merge

`.github/workflows/dependabot-auto-merge.yml` (GitHub Actions) lets the weekly **grouped** action-bump PR land itself: it enables GitHub's auto-merge (`gh pr merge --auto --merge`) so the PR merges only once the required CI checks pass. **Majors are excluded** (`if: steps.metadata.outputs.update-type != 'version-update:semver-major'`) — a major is where a breaking change hides (setup-uv v10.0.0 disabled the cache on `pull_request_target`/`workflow_run`/`release`), so those still get a human; `update-type` is the **highest** bump in the PR, so one major anywhere in the group keeps the whole PR manual. **Only `github_actions` auto-merges** (`steps.metadata.outputs.package-ecosystem == 'github_actions'` — fetch-metadata reports the branch's ecosystem segment, `dependabot/github_actions/…`, hence the underscore): the weekly grouped **uv** PR always waits for a human, because it changes production code including sign-in (authlib, cryptography, streamlit) while CI mocks Deepgram and the identity provider. `tests/test_automerge_workflow.py::test_only_github_actions_bumps_are_auto_merged` pins it — without that clause, adding the `uv` ecosystem to `dependabot.yml` would have auto-merged every non-major Python bump.

**`pull_request_target` is load-bearing, not incidental**: a `pull_request` run triggered by Dependabot gets a **read-only `GITHUB_TOKEN` that a `permissions:` block cannot elevate**, and enabling auto-merge needs write. That trade is only sound because the job **never checks the PR out and executes nothing from it** — the single invariant `tests/test_automerge_workflow.py::test_never_checks_out_pull_request_code` exists to keep true; adding an `actions/checkout` here would hand a writable token to fork-controlled code. The job is gated on the `dependabot[bot]` actor **and** `github.repository` (so a fork can't auto-merge on its own copy), `dependabot/fetch-metadata` is SHA-pinned and by default fails unless the branch carries only Dependabot-authored commits, the PR URL flows through a `PR_URL` env var (no `${{ }}` shell interpolation), and it holds **exactly** `{contents: write, pull-requests: write}` in its own file — deliberately never merged into `ci.yml`/`release.yml`, which stay free of a `pull-requests` scope.

**Two repo settings are prerequisites**, and the workflow is inert (or unsafe) without both: **Allow auto-merge** must be enabled, and `main` needs a ruleset/branch protection making `checks (3.12)` + `checks (3.13)` **required status checks**. With no required checks there is nothing for `--auto` to wait on.

## Architecture

### Core — `nova/` (imports no streamlit)

- **`config.py`** — the single source of truth for constants: `MODELS` (Deepgram `model` value → label: `nova-3-medical`, `nova-3-pharma`) with `DEFAULT_MODEL` (Medical — its first key), `LANGUAGES` (8 English variants, accepted identically by both models per Deepgram's models/languages page, so the list does not depend on the model; Pharma is English-only and Medical's `multi` is not offered), `REDACT_GROUPS` ordered **PII-first** (`pii`/`phi`/`pci`/`numbers`; PHI and Numbers labeled to flag that they strip clinical content — Numbers is Deepgram's 3+-digit rule **plus** its number-like entities — dates/times/ages, `statistics` ("medical statistics"), locations — so "500 mg" is always redacted and shorter clinical values only *sometimes*; the copy deliberately promises no value survives), `DEFAULT_LANGUAGE`/`DEFAULT_SMART_FORMAT`/`DEFAULT_DICTATION`/`DEFAULT_MEASUREMENTS`/`DEFAULT_DIARIZE` (only Smart Format on; **Measurements stays off deliberately** — Deepgram abbreviates volumes as lowercase `ml`/`l`, which ISMP lists as error-prone, so its `help=` and the README carry that warning instead), `MAX_KEYTERMS`/`MAX_UPLOADS`/`MAX_CONCURRENCY`/`MAX_FILE_SIZE` (200 MiB, pinned to match `.streamlit/config.toml`'s `[server].maxUploadSize = 200` — see Configuration), `AUDIO_EXTENSIONS` (the uploader's accepted types), and `LOW_CONFIDENCE_THRESHOLD` (`0.90`; a word is flagged when its confidence is **strictly below** it). The threshold is **display-only and deliberately not a widget**: it is never sent to Deepgram, and a sidebar control would sit inside the Run form (changing it would re-bill a transcription), would break the `_feature_opts()` ↔ `build_options` signature parity, and would let any viewer set it to 0 and silence every flag. 0.90 is a starting point — its comment says to re-evaluate on a de-identified local sample, with 0.85 as the fallback if pilots flag >20% of words. The sign-in constants live here too: `ALLOW_ANONYMOUS_ENV` (`"NOVA_ALLOW_ANONYMOUS"`, the local-development opt-out's name), `MIN_COOKIE_SECRET_LENGTH` (32), `MAX_SESSION_AGE_SECONDS` (12 h) and `MAX_CLOCK_SKEW_SECONDS` (5 min) — see `access.py`.
- **`transcribe.py`**:
  - `build_options(*, model=DEFAULT_MODEL, keyterms=None, language=None, smart_format=DEFAULT_SMART_FORMAT, dictation=DEFAULT_DICTATION, measurements=DEFAULT_MEASUREMENTS, diarize=DEFAULT_DIARIZE, redact=None)` — the kwargs dict for the Deepgram call; every parameter is keyword-only **and defaulted**, so a bare `build_options()` yields a valid default request (which is how `tests/test_transcribe.py` builds its baseline). `model` (a `MODELS` key; not validated here — `audit.run_options` refuses an unknown one before any call) + `smart_format` are **always** sent; off-by-default features are sent only when enabled — `measurements`, the Diarize toggle as `diarize_model="latest"` (Deepgram deprecated `diarize=true`, and rejects a request carrying both; the toggle, `_feature_opts` key and audit field keep the name `diarize`), and `dictation` (which also forces `punctuate=True`) — plus `keyterm`/`language` only when truthy. `redact` (typed as a single `str` by the SDK) goes through `request_options["additional_query_parameters"]={"redact":[...]}`, which is omitted entirely when unset.
  - `option_warnings(**same kwargs as build_options)` → `list[str]` — plain-text warnings for option combinations that are likely a mistake (today one rule: **Dictation + Diarize**, i.e. dictation mode on multi-speaker encounter audio). Its signature **mirrors `build_options`** (pinned by a test), so the UI passes it the same `_feature_opts()` dict and a misspelled key raises `TypeError` rather than silently skipping a check; messages name options only (no PHI) and carry no icons (the UI adds them); the defaults must yield `[]`, or every Run would warn. It advises, never overrides — auto-disabling an option was rejected because it would make the request disagree with the toggles, or silently drop a redaction the user asked for.
  - `ItemResult` dataclass `{index, label, response, error}` — `error` is `str(exc)` with no prefix; the calling adapter owns presentation.
  - `transcribe_batch(api_key, items, method, *, options, client_cls=None, as_completed_fn=None, max_concurrency=MAX_CONCURRENCY, on_progress=None)` — one shared client per batch via `ThreadPoolExecutor`; merges `options` onto each item; captures per-item exceptions (one failure never aborts the batch); sorts results back into input order. **`client_cls`/`as_completed_fn` default to `None` and resolve to this module's globals at *call time*** (not def-time) so `tests/test_transcribe.py` can `patch("nova.transcribe.DeepgramClient")` while the in-process UI wrapper injects its own globals as seams. `on_progress(done, total)` fires once per completion.
- **`results.py`** — getattr-guarded response walkers (no `st.*`): `first_alternative`, `transcript_text` (→ `.transcript` or `None`), and `diarized_segments` (groups `alternatives[0].words` into consecutive `(speaker, text)` runs, gated on an integer `words[0].speaker`; `text` uses `punctuated_word` falling back to `word`). The grouping loop lives in `_speaker_runs(words)` (a new run opens only on an integer speaker that differs from the current run's; an unlabeled word continues its run), shared by `diarized_segments` and the flagging walker. **Speaker values from the walkers stay Deepgram's native 0-based ints; the display helpers are `speaker_label` (the single home of the `+1` offset → `int | None`) and `word_token` (`punctuated_word` → `word`). `speaker_label` is reused by both the Streamlit renderer and the plain-text transcript export (`_plain_transcript`); `word_token` is used internally by `diarized_segments` and the flagging walker.** Low-confidence flagging:
  - `is_low_confidence(word, threshold=LOW_CONFIDENCE_THRESHOLD)` — reads **only** `confidence` (never `speaker_confidence`, which measures *who* spoke) and **fails toward review**: `None`/missing/`bool`/non-numeric/NaN/inf → flagged, else strict `<`. A redaction tag is never flagged.
  - `is_redaction_tag(token)` — case-insensitive `fullmatch` of `[A-Z][A-Z0-9_]*` in brackets plus trailing sentence punctuation (`[SSN_1]`, `[CREDIT_CARD_1],`, `[REDACTED]`, `[redacted].`). Tags are never flagged: the spoken content is gone, so a reviewer cannot check it. Deepgram does not document the shape of redacted tokens in `words[]`, but live PII output (2026-10-07, a synthetic call, both models) confirmed it: each tag is one word whose `punctuated_word` carries any trailing punctuation — `[NAME_1].`, `[DOB_1].`, `[OCCUPATION_1]`, `[DURATION_2]`, `[NAME_GIVEN_1]` — and the transcript text matches. `tests/test_results.py` pins those observed shapes. The confidence Deepgram assigns a tag is still undocumented.
  - `Token` — a frozen dataclass `{text, low_confidence}`; `text` is `word_token(w)` whitespace-normalized, and non-str/empty tokens are skipped.
  - `flagged_runs(response, threshold=…)` → `list[(speaker | None, list[Token])] | None`. Diarized: one run per `_speaker_runs` group. Flat: **one `(None, tokens)` run per transcript paragraph** (`re.split(r"\n\s*\n", transcript)`), consumed paragraph by paragraph — the **fidelity guard**: each paragraph's whitespace-split pieces must equal its tokens' pieces exactly (one smart-formatted token such as `(555) 123-4567` spans several pieces), with no tokens left over, else `None`. It also returns `None` with no alternative, a non-`list` or empty `words` (so a MagicMock `words` never highlights), or a non-str transcript; the UI then shows the plain transcript unhighlighted rather than a view that differs from what Deepgram returned.
  - `low_confidence_count(response, …)` → the number of flagged tokens, or `None` when `flagged_runs` is `None`.
- **`access.py`** — the sign-in policy, **fail-closed throughout**: a missing, partial, or unreadable configuration blocks the app, never downgrades it to anonymous. `decide_access(secrets: SecretsSnapshot, *, claims, allow_anonymous, opt_out_in_dotenv, trusted_headers, authlib_installed, now) -> Decision` (`kind` ∈ `allow`/`anonymous`/`login`/`deny`/`blocked`, plus `reason`, `email`, `providers`, `problem`, `reauth`, `expires_at`); the UI supplies every input, so the whole matrix is unit-tested with plain dicts. First match wins:
  1. unreadable secrets (`state="malformed"`), or the opt-out found in `secrets.toml` or in `.env` → `blocked`, **even with the opt-out set**. Streamlit mirrors top-level secrets into `os.environ`, so an opt-out seen there could have come from a copied deploy file; it counts only when neither file carries it. (`.env` can no longer put it there — the UI's `_load_dotenv` never copies it — but a `.env` carrying it still blocks, to say so.)
  2. No `[auth]`: `[access]` alone → `blocked`; `allow_anonymous` (`anonymous_opt_out`: exactly `"1"`) → `anonymous`; else `blocked` (`auth_not_configured`).
  3. A `parse_auth` problem, Authlib missing, `server.trustedUserHeaders` set (header claims override cookie claims), or `parse_policy` → `None` → `blocked`. **The opt-out is ignored whenever `[auth]` exists.**
  4. `claims.get("is_logged_in") is not True` → `login` — identity, never truthiness, and never keyed off `email` (AppTest injects `test@example.com`; a host or header can inject one). Then `session_is_fresh` false → `login` with `reauth=True`: an `iat` that is not a finite number (bools excluded), older than `MAX_SESSION_AGE_SECONDS`, or more than `MAX_CLOCK_SKEW_SECONDS` ahead, or a `provider` claim no longer configured (`"default"` ↔ the flat provider). Checked **before** `check_email`, so a stale sign-in by an account that would be refused is asked to sign in again, never denied (a test pins the order). Streamlit's cookie lasts 30 days and never re-checks the token, so this 12-hour cap is what bounds a deprovisioned user's access — for up to 12 h, since nothing asks the provider again. `decide_access` sees one moment (`now`), so the gate alone would enforce it only on full runs; the UI re-checks the allow Decision's `expires_at` everywhere else (see the access gate below).
  5. `check_email` → `deny(reason, normalized email)`, else `allow` carrying `expires_at = iat + MAX_SESSION_AGE_SECONDS` (`None` on every other kind, anonymous included). `_issued_at` is the one reader of `iat` (a finite non-bool number, else `None`), shared with `session_is_fresh`.

  `parse_auth` mirrors and tightens Streamlit's `validate_auth_credentials`: `redirect_uri` must end `/oauth2callback`; `cookie_secret` must be a str of ≥32 chars with ≥10 distinct characters and none of `change-me`/`changeme`/`replace` (it signs the identity cookie, so anyone who knows it can forge a sign-in — the template's `CHANGE-ME` must fail); providers are the flat default (all three `PROVIDER_KEYS` non-empty, or none of them) then each `[auth.<name>]` table in file order (`client_kwargs` is options, not a provider; a `_` in the name, or the reserved `default`, is a problem); zero providers is a problem. `parse_policy(access, providers)`: `allowed_email_domains` (a TOML list or a comma string — k8s directory secrets only yield strings), each stripped/lowercased/`@`-stripped and `fullmatch`ing `[a-z0-9-]+(\.[a-z0-9-]+)+`, empty → `None`; `unverified_email_providers` (default none) must name configured providers. `check_email`: `normalize_email` (strip+lower, one `@`, no whitespace, ≤254) else `email_missing`; `email_verified`, when present, must be `True` or case-insensitive `"true"`, and when absent passes only for a provider listed in `unverified_email_providers` (Entra sends none) — else `email_unverified`; the domain (`rpartition("@")`) must be an **exact** member, no suffix or subdomain match — else `domain_not_allowed`; and a Google-issued token (`iss` `https://accounts.google.com` / `accounts.google.com`) must also carry an allowlisted `hd`, since a personal Google account on a work address has a verified email but no `hd`. Unhashable claim values (a list `iss`, say) are type-checked before any set lookup. Deny/blocked `Decision`s are built only through `_deny`/`_blocked`, which require a `reason`, and a test pins that every refusal carries one, so the audit trail never meets a reasonless refusal — though `Decision.reason` is still typed `DenyReason | None`, so `audit.gate_event` narrows it (raising `AuditSchemaError("reason")` on `None`). `PROBLEM_*` strings are operator-facing and **name keys, never values**. `report_problem` logs one to the plain stdlib `nova.access` logger: with no handler configured, stdlib's last-resort handler writes it to stderr (verified under `streamlit run`, whose uvicorn logging config leaves the root logger alone).

- **`audit.py`** — the audit trail: **one JSON object per line on stdout**, PHI-free *by construction* — no field holds free text; every value is a count (`type(v) is int`, `≥ 0` — rejecting `bool` and MagicMock), a real bool (`type(v) is bool`), a member of a fixed set (`typing.get_args` of a `Literal`, or a `LANGUAGES`/`REDACT_GROUPS` key), or a random 32-hex token (`run`, `session`). Builders — `session_start()`, `access_denied(reason=)`, `logout()`, `transcription_run(run, input_kind, n_items, n_ok, n_skipped, options)` (derives `n_failed` and the `success`/`partial`/`failure` outcome; `n_items ≥ 1`, `n_ok ≤ n_items`), `transcription_rejected(input_kind, reason, n_items)`, `review_signed_off(run, result_index, n_results, edited, n_flagged)` (`n_flagged` may be `None`), `review_reopened(...)`, `transcript_downloaded(run, n_results, n_edited)` — return a frozen `AuditEvent(event, outcome, fields)`; the actor is separate (`Actor(user, auth, session)`, validated in `__post_init__`: `auth` `oidc` → a *normalized* email or `None`, `anonymous` → exactly `"anonymous"`, `none` → `None`). `emit(actor, event, *, now=None)` **re-validates everything** against `_SCHEMA` (each event's exact field set in output order, its allowed outcomes, and cross-field checks such as `n_failed == n_items - n_ok`), so a hand-built event gets no free pass, then writes the envelope `v, ts, event, outcome, user, auth, session` (`v` is `SCHEMA_VERSION`, bumped on any change to an event's field set — `2` since `transcription_run` gained `model`) followed by the fields, via `json.dumps(ensure_ascii=True, separators=(",", ":"), allow_nan=False)`. `ts` is UTC with milliseconds and `Z`; a naive `now` is refused. `AuditSchemaError` names the **field, never the value** (the value may be the PHI being refused), and an unknown key or event is refused without being named. `emit` reads the actor **by attribute**, not `isinstance` — after a hot reload the session's stored `Actor` is the previous module's class. `run_options(**same kwargs as build_options)` → `RunOptions` (keyterms become `n_keyterms`; model, language and redact groups must be known — `model` is recorded on every `transcription_run`, so the trail says which model produced a transcript; redact comes back sorted and de-duplicated; toggles must be real bools) — its signature **mirrors `build_options` parameter-for-parameter, annotations included, which is why the module has no `from __future__ import annotations`**. `actor_for(decision, session)` (allow/deny → `oidc` with the decision's email, which is `None` for an `email_missing` denial; anonymous → `anonymous`; login/blocked → `none`) and `gate_event(decision)` (allow/anonymous → `session_start`; deny/blocked → `access_denied` with the narrowed reason; login → `None`) map the access gate onto the trail. The logger:
  - `audit_logger()` is `logging.getLogger("nova.audit")` — **never `streamlit.logger.get_logger`**, which would attach Streamlit's stderr handler, and whose `logger.level` (often `error` in production) would drop these INFO lines. Under a lock it adds exactly one handler, **found again by name** (`nova.audit.stdout`), not `isinstance`: Streamlit re-imports `nova/` on a source change, which defines a new handler class while the process-wide logger keeps the old handler (an `isinstance` guard measured 5 events → 8 lines). Every call re-asserts `INFO`, `propagate=False` and `disabled=False`, so a later `dictConfig(disable_existing_loggers=True)` cannot switch the trail off (`logging.disable` still can). Installed lazily from `emit`, never at import.
  - `_StdoutHandler` sets `self.stream = sys.stdout` **inside `emit`** (under the handler lock), so it follows whatever stdout is at write time — which is what lets `capsys` see it; `StreamHandler.emit` writes the line and flushes, so no `PYTHONUNBUFFERED` is needed. It also overrides **`handleError` to re-raise**: logging's default prints a traceback to stderr and carries on, which would silently drop the line while the download it records went ahead. So a closed or broken stdout makes `emit` raise: the gate and the download fail closed, while a Run — logged only after its batch returns — raises without being able to unsend the audio. Verified under a real `streamlit run` (uvicorn keeps `disable_existing_loggers=False`): two websocket sessions × three reruns → exactly two `session_start` lines on stdout, nothing audit on stderr. stdout is shared, though: Streamlit prints its welcome banner and `  Stopping...` there, so a shipper must keep only JSON lines.

### Streamlit UI — `streamlit_app.py`

Re-imports the core constants under their old underscore names (`_LANGUAGES`, `_REDACT_GROUPS`, `_AUDIO_EXTENSIONS`, the `DEFAULT_*`/`MAX_*` names, `LOW_CONFIDENCE_THRESHOLD`, `build_options`, `option_warnings`, `transcribe_batch`) and aliases the walkers (`from nova.results import Token, transcript_text as _transcript_text, diarized_segments as _diarized_segments, first_alternative as _first_alternative, flagged_runs as _flagged_runs, low_confidence_count as _low_confidence_count, speaker_label as _speaker_label`) — preserving every existing test patch point — and imports the access policy (`from nova.access import Decision, SecretsSnapshot, anonymous_opt_out, decide_access, report_problem`, plus `ALLOW_ANONYMOUS_ENV` from config) and the audit trail as a module (`from nova import audit`, called as `audit.emit(...)` — which is also the patch point for the fail-closed download test). (`first_alternative` backs the per-result Confidence metric.)

Visual theming lives in `.streamlit/config.toml` — the **"Reading room"** clinical theme pair. `[theme]` holds only what both modes share (typography, `[[theme.fontFaces]]`, radius, border/link flags); colors live in **`[theme.dark]`** (blue-slate canvas `#11171B`, text `#E3E9ED`) and **`[theme.light]`** ("clinical white": canvas `#FFFFFF`, slate-ink text `#0F171C`), each with its own `.sidebar` table giving the Features form a surface one step off the canvas. **Both mode tables must exist**: Streamlit shows the Settings-menu Light/Dark/System switcher *only* then, and starts on "System" (the OS preference); delete either and the app locks to the other with no switcher. There is deliberately **no `base` key** — each mode table already starts from Streamlit's matching built-in. The semantic color keys (`blueColor`…`grayColor`, hues ~60° apart, same hue family per speaker in both modes) back the diarized speaker highlights, and all six `_SPEAKER_COLORS` names (`blue`/`green`/`violet`/`orange`/`red`/`gray`) must stay defined **in both mode tables**. **Every contrast figure in the config is WCAG, measured in-browser on the color Streamlit actually renders, including the ones it derives** (1.64 frontend; on the 1.65 upgrade every theme color, derived tints included, was re-checked pixel-exact in a light and dark capture): `<c>BackgroundColor` is `<c>Color` at 20% alpha in dark / **10%** in light (alerts, speaker tints), `<c>TextColor` is `<c>Color` ±15 HSL lightness (alert body text), and captions are body text at **60% opacity** — so a palette change must be re-checked on the derived pair, not the swatch. Two consequences are baked in: light mode sets the seven `*BackgroundColor` keys **explicitly at 20%**, because the 10% default left speakers 1/2/3/6 an indistinguishable pale wash (1.10–1.15:1 against white); and light `textColor` is darker than body text needs (`#0F171C`, 18:1) so that 60%-opacity captions still clear 4.5:1 on the sidebar. (Nord, the previous single-mode theme, failed four checks: `st.error` text 4.24:1, the Run label 4.03:1, primary-as-text 3.10:1, sidebar toggles 2.50:1.) **Dark-mode `primaryColor` is split by zone, and that is load-bearing.** Streamlit **hardcodes the `type="primary"` button label white** (no `primaryTextColor` exists, and the frontend runs no luminance math), and on the dark canvas no single teal can both carry a white label (≥4.5:1) *and* read as text itself (≥4.5:1) — the two bands do not overlap. So `[theme.dark].primaryColor = "#2EB3A5"` (6.98:1 on canvas: active tab label/underline, focus rings, the `st.status` progress bar) never has white text on it, while `[theme.dark.sidebar].primaryColor = "#1D7F75"` fills the Run button and the multiselect chips (white 4.83:1) and the toggles (3.33:1 on the sidebar). This depends on **the Run button — the app's only `type="primary"` — living in the sidebar**; moved to the main area its dark-mode label drops to 2.59:1. Light mode needs no split: on white the two constraints coincide, so one teal (`#177268`) is 5.76:1 both under a white label and as text. The **low-confidence flag** (`:orange[**word**]`) renders in the *derived* orange text color, not `orangeColor`: measured in-browser on the output panel (whose background is the canvas) at **#EDBE8C 10.62:1** dark / **#854B14 6.97:1** light, bold at weight 600. Bold is the non-color cue WCAG 1.4.1 needs — in dark mode orange differs from body text by only ~1.4:1 — so keep other bold out of transcript body text; and the flag has no background, so it cannot be read as a `:{color}-background` speaker chip. **`borderColor` is raised in both mode tables (not the `.sidebar` tables) for the review checkbox**: an unchecked `st.checkbox` is drawn only by its `borderColor` outline (1.64 bundle: `lightenedBg05` fill, `borderColor` border; `borderColor` renders identically on 1.65), which WCAG 1.4.11 needs at 3:1 against the canvas — the old `#36434D`/`#C8D2D9` were 1.78:1/1.54:1, the new **`#546878`/`#7E95A5` measure 3.12:1 each** in-browser, for both the unchecked checkbox border and the `st.text_area` outline, which render exactly `borderColor` on the canvas. Against the fills *inside* those borders they are lower (the text_area's own fill 2.75:1 dark / 2.80:1 light; the dark checkbox's derived `#161D23` interior 2.94:1). 1.4.11 is met on the outer boundary, against the canvas, so do not quote more than that. A checked box fills with the main `primaryColor` (6.98:1 dark / 5.76:1 light on the canvas); its white tick is not relied on. The change also darkens every main-area widget and container border (the output panel, metric cards, the uploader); the sidebar tables keep their own softer borders, since the checkbox renders only in the main area. The sidebar's **signed-in email** is `st.text` — full-opacity body text, measured in-browser at **16.69:1** light / **13.15:1** dark on the sidebar — because inside the "Signed in as" caption Markdown autolinked it and the 60% opacity dimmed that link to 2.40:1 / 3.47:1 (a code span avoids the autolink but still fails at caption opacity). Typography loads **Inter** (`font`, UI/headings) and **JetBrains Mono** (`codeFont`, for any code rendering) **self-hosted** from `static/` (served at `app/static/*` via `[server].enableStaticServing`) with a system-stack fallback — Streamlit's bundled theme templates pull fonts from Google Fonts and that is deliberately not done here, so no third-party font CDN is contacted; `baseFontSize = 14` and the six-entry `headingFontSizes` tame Streamlit's oversized defaults. Pure config, so it never touches the test suite. `st.set_page_config(page_title=…, page_icon="🩺", layout="wide")` is the first Streamlit command.

1. **Access gate** — `_access_gate()` runs at module level **right after the title and subtitle, before the API-key resolution** (`access_decision = _access_gate()`, then `st.stop()` on `None`). It feeds `decide_access` `_secrets_snapshot()` (a guarded read of `[auth]`, `[access]`, and the opt-out's presence through the **public** `st.secrets`, so AppTest's `at.secrets` drives it; a `StreamlitSecretNotFoundError` is `missing` only for `error_id == "no-secrets-found"`, anything else `malformed`), `st.user.to_dict()`, `anonymous_opt_out(os.environ)`, `_dotenv_has_opt_out()`, `bool(st.get_option("server.trustedUserHeaders"))`, `_authlib_installed()` (`find_spec("authlib")`) and `time.time()`; the two probes are test seams. Both opt-out detectors go through `_names_opt_out(keys)`, a **presence** check over the file's keys (iterating `st.secrets` / `dotenv_values()`), **case-insensitive** because Windows' `os.environ` is — a lowercase `nova_allow_anonymous` in either file lands there as the real variable — and value-blind, because Streamlit mirrors a top-level secret as `str(value)` (a TOML `= 1` becomes `"1"`). It renders:

   | decision | renders | returns |
   |---|---|---|
   | `anonymous` | `st.warning(ANONYMOUS_MODE, icon=":material/no_accounts:")` — detailed, since only an operator who opted out ever sees it | the Decision |
   | `blocked` | `st.error(SIGN_IN_UNAVAILABLE)` **only** — visitors get no configuration detail; `report_problem(decision.problem)` once per session (`access_problem_logged`) | `None` |
   | `login` | `st.info(SIGN_IN_PROMPT, or SESSION_EXPIRED when reauth, icon=":material/lock:")` + one **secondary** `st.button` per provider (`"Sign in"` / `"Sign in with <Name>"`, `key=f"sign_in_{name or 'default'}"`, `icon=":material/login:"`, `on_click=st.login, args=(provider,)`) | `None` |
   | `deny` | `st.error(DENY_MESSAGES[reason] + DENY_SUFFIX)` naming the Markdown-escaped email, then the Sign out button | `None` |
   | `allow` | nothing here — the sidebar opens with `_account_panel(email)` | the Decision |

   - **`st.login` is only ever a button callback, never called on render**: under AppTest it raises, because `at.secrets` is invisible to Streamlit's own `validate_auth_credentials` (which reads `secrets_singleton`).
   - **In a bare-mode import (pytest) `st.stop()` is a no-op**, and ty narrows `access_decision` to `Decision` after it (`st.stop` is `NoReturn`), so code below the gate must still tolerate `None` — the sidebar's account check does, and `TestBareImport` imports the module down both branches.
   - `access_ok` is rewritten on **every** full run (`False` before any stop, and until the gate's audit record is written — if `_audit_gate` raises, the session stays closed), together with `access_expires_at` (the Decision's `expires_at`). `_access_ok()` is `access_ok is True` **and** `not _expired(access_expires_at)` — `None` never expires (anonymous); anything but a number, or NaN, counts as expired. `_render_output`, `_on_edit` and `_on_review` return immediately unless it holds: a fragment rerun or a widget callback skips the gate, a stopped run leaves the fragment registered, and an open page can keep using the review panel for hours with no full run. When the flag is set but the sign-in has expired, `_render_output` calls `st.rerun(scope="app")` (a callback cannot rerun), so the next panel interaction lands on the full run's `SESSION_EXPIRED` screen; that full run's gate clears the flag, so it cannot loop. The download callable checks its own captured expiry (see the renderers).
   - **Audit** (`_audit_gate`, every full run): `audit_session = st.session_state.setdefault("audit_session", uuid.uuid4().hex)`, then `audit_actor = audit.actor_for(decision, session)` — rewritten each full run, which also refreshes its class after a hot reload — and the `audit.gate_event(decision)` line **only when `decision.kind` differs from `audit_gate_state`**, so reruns log nothing new. The sign-in screen logs nothing (`gate_event` → `None`): `st.login` redirects into a new session, whose `session_start` is the login record. It runs at import too (bare mode), so `TestBareImport` asserts the line on both branches. `_audit_actor()` reads `audit_actor` back and **raises `RuntimeError` when it is missing — never a fallback to anonymous**, which would hide a broken gate; no `isinstance` check (hot reload).
   - **Sign out** (`_sign_out`, the button callback) logs `audit.logout()` under the session's actor, then runs `_purge_session()` then `st.logout()`, nested `try/finally` — `try: emit finally: try: purge finally: logout` — so signing out never depends on the audit line or the purge. The purge **deletes** `responses`, `audio_sources`, `run_id`, `run_model`, `keyterms`, the audit identity and review record (`audit_actor`, `audit_review`) and every `transcript_*` / `reviewed_*` / `uploads_*` / `recording_*` key outright — the sign-out rerun stops at the gate, and Streamlit drops an unrendered widget's state only after a run that *completes* — then increments `input_nonce` (the uploader and recorder are keyed `uploads_{nonce}` / `recording_{nonce}`, so they return as new, empty widgets, browser side included) and sets `access_ok = False`. `st.logout` clears `st.user` and redirects through the provider's `end_session_endpoint` when it has one; Google has none, hence `SIGN_OUT_NOTE` under the button (and the template's `client_kwargs = { prompt = "login" }` hint for Entra/Okta/Auth0). Authlib forwards only `prompt`/`login_hint`/`nonce`/`response_mode` from `client_kwargs`, but a **named** `[auth.<name>]` table can send any authorize parameter: Streamlit maps each of its keys to Authlib's `<NAME>_<KEY>` config, and `authorize_params = { max_age = 0 }` there puts `max_age=0` on the authorize URL (verified against 1.64's own OAuth client). The flat default provider cannot — `generate_default_provider_section` copies only the client keys, `client_kwargs` and `expose_tokens` — so the template's commented hint moves Google into `[auth.google]`, marked "verify with your identity provider". `st.user` is read from the cookie **once per websocket connection**, so Sign out ends only that tab's session: other open tabs keep theirs until they reload or hit the 12-hour cap (README known limits).
2. Resolves `DEEPGRAM_API_KEY` — environment first (`.env` via python-dotenv), then `_secret_api_key()`, a guarded `st.secrets` read for deployed hosts with no `.env`; prompts inline if both come up empty.
3. `_transcribe_batch(api_key, items, method, **opts)` — a thin UI adapter over `nova.transcribe.transcribe_batch`, where `**opts` is the `_feature_opts()` dict (`model`/`keyterms`/`language`/`smart_format`/`dictation`/`measurements`/`diarize`/`redact`) forwarded straight into `build_options`. It:
   - builds the playback `sources` up front from each item's `request` bytes — `_playback_source` keeps small audio but stores `None` over `MAX_PLAYBACK_BYTES` (25 MB);
   - drives a live `st.status` region (nested `st.progress` bar + label updated via an `on_progress` callback, auto-collapsed to `state="complete"` on finish);
   - renders one `st.error` per failed item (these land *after* the batch finishes rather than interleaved — no test pins the timing);
   - **unconditionally** writes `st.session_state["responses"]` and the parallel `["audio_sources"]`, so a fully-failed run clears stale results — and a fresh `["run_id"]` (`uuid.uuid4().hex`, 32 hex), also unconditional so a fully-failed run rotates it too, which keys the review widgets (see Session state below);
   - fires a one-shot completion `st.toast` (`_completion_toast` — success / partial / all-failed);
   - passes the module-global `DeepgramClient`/`as_completed` as seams;
   - returns `len(ok)`, the success count.

   A `None` source renders a `PLAYBACK_TOO_LARGE` caption instead of a player — and unlike the oversize-upload error, that caption **hardcodes its own "25 MB"** rather than deriving it, so changing the constant alone leaves the caption lying.
4. `_process_inputs` — wraps `_transcribe_batch` for `(name, bytes)` pairs (the uploads, or the single recording) via `transcribe_file`, the only method the UI calls, and returns its success count.
5. `_feature_opts()` — reads the Features control values (the **sidebar** form, not a tab) from `st.session_state` (by widget `key`, falling back to the `DEFAULT_*` constants — except `keyterms`/`redact`, which fall back to `[]`).
6. `_run(api_key, uploaded_files, recording)` — the Run handler: resolves `actor = _audit_actor()` **first**, `st.info`s when both inputs are populated, reads `_feature_opts()` **once** and projects it with `audit.run_options(**opts)` — both before any Deepgram call, so a missing actor or an unknown option fails before audio leaves the app — shows one `st.warning` per `option_warnings(**opts)` message (advisory — the run still proceeds), then validates and transcribes the higher-priority input, **Upload → Record** (file count/size; recording duration via a guarded `wave.open`), via `_process_inputs` with `**opts`. Each outcome logs exactly one line: `transcription_run` after the batch (`run=st.session_state["run_id"]`, `n_items`/`n_ok` from `_process_inputs`' return, `n_skipped` = oversize uploads, 0 for a recording), or `transcription_rejected` — `too_many_files`, `all_oversize` (a branch of its own: uploads present but none valid), `recording_unreadable`, `recording_too_long`. No input logs nothing. **Never** hand a builder `r.label`, `r.error`, `str(exc)`, keyterms, transcript text or a URL — Deepgram's `ApiError.__str__` includes headers and body.
7. Renderers:
   - `_display_transcript` — a `_display_metrics` row of `st.metric` cards (Duration + alternative-level Confidence, via `_result_metrics`, plus **Low-confidence words** from `_low_confidence_count`; each rendered only when available, so a missing count never reads as "0 to check"), then `_flagged_runs(response)`:
     - **runs available** — a caption first, **always**: `LOW_CONFIDENCE_LEGEND` (`:material/flag:` + "Words in **bold orange** scored below 90%…") when any token is flagged, else `NO_FLAGS`; both derive the percentage from `LOW_CONFIDENCE_THRESHOLD` and both say unmarked words can still be wrong **and that missed speech leaves nothing to flag** (a synthetic-audio test saw Nova-3 Medical silently drop ~40-word spans on 8 kHz audio; omissions are invisible to word confidence). They are plain caption text on purpose — a colored sample at caption opacity (60%) would fall to ~2.8:1 in light mode. Then one `st.markdown` per run via `_flagged_markdown` (tokens escaped, flagged ones wrapped as `:orange[**…**]`): a flat paragraph renders bare; a diarized run is prefixed with the **color-highlighted** `:{color}-background[**Speaker N:**]` label from `_SPEAKER_COLORS`, **1-based** display.
     - **`None`** — the plain escaped transcript under `st.caption(NO_CONFIDENCE)` ("…review every word against the audio"), nothing for a blank transcript, or `st.caption(NO_TRANSCRIPT)` when the response has no results.

     `_plain_transcript` is **unchanged** — still `diarized_segments` / `transcript_text` — and now **seeds each result's export editor**, so an unedited download matches the highlighted view modulo whitespace, since both derive from the same words (or from the fidelity-guarded transcript). The highlighted view always shows Deepgram's original tokens; the editor holds plain text with no highlights.
   - `_review_controls(run_id, index, response, total)` → `(text, reviewed)` — per result, under its highlighted view: an `st.text_area(EDIT_LABEL, value=_plain_transcript(response), key=_text_key(…), height="content", help=EDIT_HELP, on_change=_on_edit, disabled=_is_reviewed(…))` then an `st.checkbox(REVIEWED_LABEL, key=_reviewed_key(…), on_change=_on_review)` with **no `value=`**. With `total > 1` both labels carry `" (i of n)"` — the position, never the filename. The rules that make it safe:
     - **Seeded via `value=`, never via session state** — doing both logs Streamlit's duplicate-default warning; with a user key a new `value=` never resets the widget, which is why the keys carry the `run_id`.
     - **Always rendered** — no lazy `.open` guard, expander-toggle, or edit mode: an unrendered keyed widget loses its value (`persist_state` does not help).
     - **Frozen once reviewed** — `disabled` while its checkbox is `True` (identity, not truthiness), so no edit can be typed after sign-off and then miss the download (a text area commits only on blur or Ctrl/⌘+Enter). A disabled widget stays registered and keeps its value; unchecking is the only way back to editing, and it re-locks Download.
     - **The gate uses the return values, never the keys read above the widgets.** Streamlit 1.64 and 1.65 (pinned by AppTest) skip a disabled widget's callback and discards its incoming value (a stale UI's late edit, or a forged message) — but the discard happens only when the widget *registers*, so a `st.session_state[key]` read taken earlier in the run still returns the dropped text. Reading the keys at the top of the fragment would put unreviewed text into a "reviewed" export; the AppTest forge case pins this (and fails against that shape).
     - `_on_edit` clears a set Reviewed flag and toasts `REVIEW_CLEARED`. It only fires with the flag set when an edit and a check land in the same rerun — which in a browser is the **ordinary** "type, then click Reviewed" path (a text area commits on blur, and the click is the blur; a headless-Chrome review saw the first click revert 7/7). **The clear is load-bearing, not defensive**: left set, the flag renders the editor `disabled` in that very run, and Streamlit drops a disabled widget's incoming value *when it registers* — so the box would stay checked over the pre-edit text with the correction silently gone (verified under AppTest; the smoke run pins that the edit survives). Hence the toast and `EDIT_HELP`'s "press Ctrl/⌘+Enter before checking Reviewed", rather than keeping the check.
     - **Review audit** — `_on_review` (every change) and `_on_edit` (only when it cleared a flag) call `_audit_review`, which logs `review_signed_off` (`edited` = the editor's session text ≠ `_plain_transcript`, `n_flagged` = `_low_confidence_count`) or `review_reopened` **only when the flag differs from `audit_review`** — `(run_id, frozenset of indexes logged as signed off)`, reset by a new `run_id`. Keyed to state, not callbacks, because an edit + check in one rerun runs both callbacks in an unguaranteed order: checkbox-first logs signed-off then reopened; editor-first — what 1.64 and 1.65 do, pinned by AppTest — leaves the flag where it started and logs **nothing**. Emitting straight from each callback (the obvious wiring) logged two `review_reopened` lines there for a sign-off that was never logged. A result index no longer in `responses` logs nothing.
   - `_transcript_download(responses, reviews, run_id)` — one `.txt` `st.download_button(key="download_transcripts", on_click="ignore")` over the whole batch (a multi-result batch becomes one combined file, `_export_blob`: a `Model: Deepgram <name>` line when the run's model is a known `MODELS` key, then `name` line + text per result, blank-line separated), **locked until every result is reviewed**: labelled `f"Download locked — {k}/{n} reviewed"` with `help=DOWNLOAD_LOCKED_HELP`, else `DOWNLOAD_LABEL`. While locked it carries **`data=""`** — the server-side half of the gate, since `disabled` is only enforced in the browser on the deferred-file path (the `deferred_file_id` ships in the proto and `execute_deferred` has no disabled check). Unlocked, `data` is `_deferred_export(named_texts, actor, event, expires_at)`: a **deferred** zero-arg callable (assembled on click, not every rerun) closing over the editors' text, `_audit_actor()`, an already-validated `audit.transcript_downloaded(run=run_id, n_results=n, n_edited=…)` (`n_edited` = results whose editor text ≠ `_plain_transcript`), and `access_expires_at`, all captured at render. A click reruns nothing, so the button can outlive the sign-in on an idle page: past the expiry the callable raises `PermissionError(DOWNLOAD_EXPIRED)` before logging or building anything. Streamlit runs it on a worker thread with **no ScriptRunContext**, so it must never touch `st.*` (session state included). It checks the expiry, emits the event, **then** builds the file, so the line is 1:1 with files generated — every click, since each click re-runs it — and if the line cannot be written it raises, **failing the download closed** (see the PHI policy for why that exception must be PHI-free). `on_click="ignore"` skips the rerun a click would otherwise trigger.
   - `_output_panel(responses, audio_sources, run_id)` — pinned players + fixed-height container or placeholder, calling `_display_transcript` then `_review_controls` per result, and **returning** the `(text, reviewed)` pairs in result order (`[]` for the placeholder); `None` source → `PLAYBACK_TOO_LARGE` caption.
   - `_display_audio` (bytes only; MIME from extension via `_AUDIO_MIME`, default wav) and `_escape_markdown` (backslash-escapes `` \ ` * _ [ ] ~ $ ``). **`$` is load-bearing**: Streamlit's Markdown always enables single-dollar math, so unescaped smart-formatted currency such as `$20-$30` could render as a formula with its dollar signs dropped (verified in-browser that the escaped form renders literally, with no KaTeX).

   Per-speaker highlighting and the low-confidence flags use native Markdown color directives (no raw HTML/CSS), so they stay test-safe. Status callouts (`st.error`/`st.warning`/`st.info`) and the completion `st.toast` carry Material Symbol icons (`:material/…:`).
8. Layout — `layout="wide"`, a `st.caption` subtitle below the title, the access gate's output (the anonymous banner, when shown, sits above the columns), then two zones:
   - **Sidebar (`st.sidebar`)** — when signed in (not anonymous), the **account block** first (`_account_panel`: a `:material/account_circle:` "Signed in as" caption, then the email as **`st.text`** — never inside the caption, where Markdown autolinks it into a `mailto:` in link color that the caption's 60% opacity dims below AA (see the theme paragraph); plain text needs no escaping — then the secondary Sign out button and `SIGN_OUT_NOTE`); then the **Features** controls (canonical home for app-level settings, freeing the full main width for output): a `:material/tune:` caption over an `st.form("features", border=False)` so edits don't rerun until submit — Model, Language, Keyterm Prompting, Smart Format, Diarize, Dictation, Measurements, Redact — closed by a full-width `st.form_submit_button("Run", icon=":material/graphic_eq:", width="stretch")` carrying a `help=` hint when disabled.
   - **Main area** — a side-by-side `st.columns(INPUT_OUTPUT_RATIO)` split (`(2, 3)`), which stacks inputs-first at ≤640px:
     - **left** — the two Material-icon'd audio input tabs, their widgets keyed by `input_nonce` (Upload ≤100 files/200 MB each; Record `st.audio_input` ≤30 min (`MAX_RECORDING_SECONDS`; the error derives its minutes from it — at the default 16 kHz a recording passes `MAX_PLAYBACK_BYTES` at ~13.6 min, so longer ones get the `PLAYBACK_TOO_LARGE` caption in the output panel)). Run feedback (validation callouts, the `st.status` progress region, per-item errors) renders here too (`with input_col: _run(…)`), so it never pushes the output's top edge down.
     - **right** — a single output view with **no tabs**: `_render_output` (an `@st.fragment`, so an applied edit or a Reviewed check reruns only that panel) renders a `st.caption(":material/description: Transcript")` header (styled like the sidebar's settings caption; with results it appends ` · <model name>` from `run_model`), reserves the download row with `st.empty()`, renders `_output_panel`, and only then fills the row via `with download_row: _transcript_download(responses, reviews, run_id)` — the button sits above the panel but must be built from the review widgets' return values, which exist only once they render. (An empty placeholder is `display: none`, so the empty state gains no gap.) The review widgets live here, outside `st.form("features")`, which is load-bearing: a `download_button`, or a text area with `on_change`, raises inside a form.

     `OUTPUT_HEIGHT` (480) is **measured, not arbitrary**: it was sized so the panel's bottom clears the fold of a ~840px-tall viewport (1080p minus browser chrome) in the tallest case — a single result, with the download row and pinned player above it. That measurement was taken with a tab strip above the panel (then spanning y≈334–814); the caption header that replaced it is shorter, so the panel still clears the fold, but 480 is no longer shown to be the tallest value that does. Streamlit has no viewport-relative height (`height="stretch"` needs a bounded parent), so a fixed value is the only option, and one that crosses the fold reintroduces a page scroll nested around the panel's own scroll. The review editor and checkbox add nothing above the panel — they render *inside* its scroll container, and `height="content"` keeps the editor from nesting a second scroll region — at the accepted cost that a long transcript scrolls past twice (highlighted view, then editor). Sign-in adds nothing above the panel either — the account block is in the sidebar — while the dev-only anonymous banner pushes the main area down by one callout (~60px), exactly as the "API key required" warning does; the sign-in, denied, and unavailable screens have no panel at all. The empty-state placeholder copy is deliberately direction-free ("Select audio, then…") because the inputs sit *beside* the output on desktop but *above* it once stacked.

## Configuration

Two env vars. `NOVA_ALLOW_ANONYMOUS` (`ALLOW_ANONYMOUS_ENV`) is the local-development opt-out from sign-in — honored only as exactly `"1"`, only with no `[auth]`, and only from the **process** environment (`NOVA_ALLOW_ANONYMOUS=1 uv run streamlit run streamlit_app.py`): found in `.env` or `secrets.toml` it blocks the app instead, so it belongs in neither `.env` nor `.env.example`. The other is `DEEPGRAM_API_KEY` (server-side only), loaded from `.env` (gitignored; see `.env.example`) by `_load_dotenv` — python-dotenv's `dotenv_values()`, copied into `os.environ` without overriding a set variable, like `load_dotenv()`, **except the opt-out, which is never copied** (in any letter case). That filter is load-bearing: `os.environ` outlives a script run, so a `load_dotenv()`-copied opt-out survived its deletion from `.env` until a restart, and the next run opened anonymously. `st.secrets` is the deployment fallback (`_secret_api_key()`) for hosts that have no `.env` — Streamlit Community Cloud writes dashboard secrets to a `secrets.toml` instead; the UI still prompts inline if both come up empty. **That read must stay guarded**: `st.secrets` raises `StreamlitSecretNotFoundError` on *every* access — `.get()` and `in` included — when no secrets file exists, which is the normal local setup here, so an unguarded probe would crash the app on import. Touching `st.secrets` at all is also the only thing that mirrors top-level secrets into `os.environ`, which is why an environment-only read comes up empty on Cloud even when the secret is configured.

**Sign-in lives in `.streamlit/secrets.toml`** — `[auth]` (Streamlit's OIDC config: `redirect_uri`, `cookie_secret`, the flat default provider, optional `[auth.<name>]` providers and `client_kwargs`) and `[access]` (`allowed_email_domains`, `unverified_email_providers`) — never `config.toml`, which drops unknown keys and is tracked in a public repo. As nested tables they ship through the same channel as the secrets and are never mirrored into `os.environ`. The tracked template is **`.streamlit/secrets.toml.example`** (Streamlit loads only exact `secrets.toml` paths, so it is inert; see the hooks section for why the name matters). It **fails closed as shipped** — its `cookie_secret = "CHANGE-ME"` is refused — and `tests/test_access.py` loads it through Streamlit's own secrets parser to pin that, and that it passes once the secret is replaced. It holds only tables: a top-level value would be mirrored into `os.environ`, overwriting a real env var of the same name. With sign-in configured the app also contacts the OIDC identity provider — server side for its metadata, JWKS and token endpoints, and by browser redirect to sign in and out — so "the only traffic is the Deepgram API call" below holds only without `[auth]`.

**Secrets are guarded in both directions**, because `block-secrets.sh` structurally cannot cover reads — a PreToolUse hook matching `Edit|Write|MultiEdit` never sees a `Read`. The **write** side is the hook; the **read** side is a `permissions.deny` block in the same tracked `.claude/settings.json`, denying `Read` on `.env`, `.env.*`, `.envrc`, `.envrc.*` **at the repo root only** (those rules are `./`-anchored, and `*` does not cross a `/`), plus `secrets.toml` / `.secrets.toml` at the root **and at any depth** (`./**/`). That asymmetry is deliberate but worth knowing before you rely on it: the write hook matches `*.env`/`*.envrc` at **any** depth, so a nested `config/.env.local` is unwritable yet still **readable**. Add `./**/` variants before putting a real env file in a subdirectory.

Two consequences worth knowing before editing those rules:

- **`.env.example` is collateral, deliberately.** Deny rules beat `allow` rules unconditionally, and the matcher supports no negation (neither extglob `!(example)` nor a `[!e]` class — both are accepted silently and match nothing, which is *worse* than an error). So `Read(./.env.*)` also blocks the tracked template, and since `Edit` requires a prior `Read`, Claude can no longer maintain `.env.example` — you edit it yourself. This is the fail-closed choice: enumerating `.env.local` / `.env.production` / … instead would leave an unanticipated `.env.staging` readable, which is the same hole class as the `.envrc.local` gap above. A loud block on a tracked template beats a silent miss on a real secret.
- **Permission rules are per-tool, so `cat .env` via Bash is still unguarded.** Closing that would mean parsing shell, which is not worth attempting; treat it as a known limit rather than a rule to add.

The Streamlit UI's visual theme is non-secret config in `.streamlit/config.toml` (tracked); secrets (`.env`/`.env.*`, `.streamlit/secrets.toml`) are gitignored. The theme self-hosts Inter / JetBrains Mono as WOFF2 in `static/` (served at `app/static/*` via `[server].enableStaticServing`), so **no request leaves the app to a third-party font CDN**; faces fall back to the system sans/mono stack if they fail to load. `[browser].gatherUsageStats = false` closes the other outbound path: Streamlit's anonymous usage telemetry **defaults to `true`** and posts to `webhooks.fivetran.com` (5 requests per page load, measured). It carries usage metrics rather than transcript content, but an unaudited third-party beacon from a clinical-transcription page is not worth defending under the PHI policy — with both set, the only traffic the app originates is the Deepgram API call itself (plus the identity provider, when sign-in is configured). See `static/FONTS.md` for attribution (both are SIL OFL 1.1). The `[server]` block also pins `maxUploadSize = 200` (MB) — the effective per-file upload cap — which must stay in sync with `nova.config.MAX_FILE_SIZE`: Streamlit silently caps uploads at its 200 MB default, so a larger app-side guard would be unreachable (as the former 2 GiB cap was). The oversize `st.error` derives its size from `MAX_FILE_SIZE` (`f"Skipped (exceeds {MAX_FILE_SIZE // (1024 * 1024)} MB): …"`), keeping the limit in one place.

## PHI logging policy (non-negotiable)

- **Never log** audio bytes, transcripts, segments, raw responses, keyterms, filenames, or full URLs. Treat every Deepgram request/response as carrying PHI.
- **The audit trail (`nova.audit`, stdout) carries no PHI by construction**: counts, real bools, fixed-set members and random ids only — no free-text field exists. Its `user` is the staff email (workforce identity, which HIPAA audit controls — unique user identification, log-in monitoring — ask for; not patient PHI), `"anonymous"`, or null. Keyterms reach it only as `n_keyterms`; filenames, `ItemResult.error`/`str(exc)`, transcript text and URLs must never be passed to a builder. A rejected value raises `AuditSchemaError` naming the **field**, never the value. The trail is still personal data (staff emails, refused accounts' emails): operators restrict access and set retention.
- **The download's deferred `data` callable raises only on a PHI-free path.** Streamlit logs a failing one with `_LOGGER.exception` (traceback included), so `_deferred_export` closes over plain strings and a pre-validated audit event captured at render, and its only failure modes are an expired sign-in (`PermissionError(DOWNLOAD_EXPIRED)`, fixed text) and the audit line not being written — both deliberate, failing the download closed — whose exceptions (`AuditSchemaError`, or the stream's own write error, which `_StdoutHandler.handleError` re-raises) carry no transcript text. Anything added to that callable must keep that true.
- **Sign-in logging names keys, never values.** The only stderr access line is `report_problem`'s operator message, built from the `PROBLEM_*` constants; visitors on a blocked deploy see only `SIGN_IN_UNAVAILABLE`. A denied account's email is shown to that user and recorded only as the `user` of its `access_denied` audit line on stdout — never on stderr, nowhere else (the AppTest parent asserts both).
- **Sign-out purges the session's PHI** (results, review edits, uploads, the recording, keyterms) before `st.logout()`; see the access gate.
- A **Deepgram BAA** is the operator's responsibility before real PHI flows through the app.

## Dependencies

Managed by uv via `pyproject.toml` + `uv.lock`. **Every dependency is pinned exactly (`==`)**, runtime and dev alike, with dev deps in a PEP 735 `[dependency-groups] dev` table (so a plain `uv sync` installs them). `uv add` writes a `>=` range by default — rewrite it to `==` and re-run `uv lock`, or the pin convention and CI's `uv sync --locked` drift apart.

Runtime: **deepgram-sdk** (v7), **streamlit** — as **`streamlit[auth]==1.65.0`**, the extra that brings Authlib for `st.login` — plus an explicit **authlib** pin (`1.8.0`; the extra itself only asks for `Authlib>=1.3.2`), and **python-dotenv**. The auth extra adds joserfc, cryptography, cffi and pycparser transitively (httpx was already locked via deepgram-sdk). `.github/dependabot.yml` tracks them too (a weekly grouped `uv` PR, never auto-merged; security updates arrive ungrouped).

Dev: **ruff**, **ty**, **pytest**, **PyYAML** (used by the config-guard tests — `tests/test_ci_workflow.py`, `tests/test_release_workflow.py`, `tests/test_automerge_workflow.py`, `tests/test_dependabot.py` — to parse the workflow / Dependabot YAML), **watchdog** (lets `streamlit run` use native file-system events for hot-reload instead of polling; dev-only, so deployed hosts don't need it)

Ruff lint config: `[tool.ruff.lint]` selects `E`/`F`/`I`/`UP`/`B` and ignores `E501` (line length is formatter-driven); `combine-as-imports = true` sits in the **`[tool.ruff.lint.isort]`** sub-table (keeps the UI's aliased re-exports in one block). The sub-table is required, not stylistic — `combine-as-imports` is an isort setting, and under `[tool.ruff.lint]` it is an unknown field that makes ruff refuse to load the config at all, failing **both** the `ruff format` and `ruff check` gates.

**deepgram-sdk** notes (v7, project pins `7.12.0`): options are keyword args (not `PrerecordedOptions`), API key passed explicitly to `DeepgramClient(api_key=...)`, responses are Pydantic models. The namespaced client path is `client.listen.v1.media.transcribe_file(request=<bytes>)` — the only method the UI calls — with a sibling `transcribe_url(url=<str>)` that the UI no longer offers but the core's generic `transcribe_batch(method=…)` can still forward to (`tests/test_transcribe.py` exercises both); most options (`model`, `smart_format`, `keyterm`, `language`, `dictation`, `measurements`, `diarize`, `punctuate`) are typed keyword args. `redact` is typed as a single `str`, so multiple redaction groups go through `request_options={"additional_query_parameters": {"redact": [...]}}` (repeated query params).

- **Response-type union**: the transcribe methods are typed to return `ListenV1Response | ListenV1AcceptedResponse`. The UI only ever receives `ListenV1Response` (which has `results`) because it never passes `callback=`; `ListenV1AcceptedResponse` (callback/async mode) carries only `request_id` and no `results`. `nova.results.first_alternative` guards the `.results` access so the walkers degrade gracefully if that ever changes.
- **Version**: pinned to `deepgram-sdk==7.12.0` (requires Python 3.10+, satisfied by this app's 3.12 floor). The pre-recorded REST surface and the response-type union are identical from v5 through v7; the breaking changes across those majors were confined to the websocket/streaming/TTS/agent APIs this app does not use (see [`docs/Migrating-v5-to-v6.md`](https://github.com/deepgram/deepgram-python-sdk/blob/main/docs/Migrating-v5-to-v6.md) / [`docs/Migrating-v6-to-v7.md`](https://github.com/deepgram/deepgram-python-sdk/blob/main/docs/Migrating-v6-to-v7.md) in the deepgram-python-sdk repo).

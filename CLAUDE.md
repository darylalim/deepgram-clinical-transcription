# CLAUDE.md

## Project Overview

Streamlit application for medical transcription using Deepgram's Nova-3 Medical model.

A Streamlit-free core (`nova/`) is consumed **in-process** by the Streamlit UI (`streamlit_app.py`): it builds options, runs batches, and parses responses, keeping that logic framework-free and unit-testable independent of the UI.

## Commands

```bash
uv sync                                                          # Install dependencies
uv run streamlit run streamlit_app.py                           # Run the Streamlit UI
uv run ruff check .                                              # Lint
uv run ruff format .                                            # Format
uv run ty check .                                               # Type check
uv run pytest                                                    # Test
```

When working with Python, invoke the relevant `/astral:<skill>` for uv, ty, and ruff to ensure best practices are followed.

## Claude Code hooks

`.claude/settings.json` (tracked/shared) wires **two** scripts in `.claude/hooks/`, each launched via `bash` with `$CLAUDE_PROJECT_DIR` so they use the project's pinned tools; **personal overrides belong in `.claude/settings.local.json` (gitignored)**. Newly added or changed hooks require review before they fire (run `/hooks`, or restart the session). Both are covered by `tests/test_hooks.py`.

The two have **deliberately opposite failure modes**, and the asymmetry is the design: a *security guard* that cannot do its job must refuse, while a *quality gate* that cannot do its job must stand aside — a blocking Stop hook unable to read its own loop guard would wedge the session.

- **`block-secrets.sh`** (PreToolUse `Edit|Write|MultiEdit`) — denies edits to `.env` / `.env.*` / `secrets.toml` / `.secrets.toml` / `.envrc` / `.envrc.*` **case-insensitively** (so `.ENV` can't slip past on a case-insensitive filesystem) with exit 2, leaving the tracked `.env.example` editable. **Fails closed** (exit 2) on *both* unreadable-event paths — `jq` missing, and event JSON that `jq` cannot parse — rather than silently allowing the edit. Note `.envrc.*` is explicit: `*.env.*` requires a literal `.env.` substring, so `.envrc.local` (direnv's `source_env_if_exists` target) once walked straight through, and `.gitignore` carries the matching entry.
- **`gates.sh`** (Stop) — runs the four project gates **whole-project** when a turn finishes: `ruff format .` (which **applies**, so CI's `--check` never fires), then `ruff check .`, `ty check .`, and `pytest -q` (which only **report**). Blocks the stop (exit 2) with each failing gate's output truncated *individually*, so a long pytest failure cannot push the ruff/ty findings out of the message. A `stop_hook_active` guard prevents an infinite fix-loop — note it blocks **exactly once per stop chain**: the retry short-circuits without re-running, so a claimed fix is not re-verified by the hook.

**Why whole-project, and why not PostToolUse.** A former `py-checks.sh` ran `ruff`/`ty` per edit against the **single edited file**. That is blind in the way that matters here: `streamlit_app.py` re-imports ~15 names from `nova/` under aliased underscore names, so changing a `nova/` signature type-checks clean on its own file while the caller it just broke is never examined — the gate reports PASS on exactly the change most worth catching. Its `ruff check --fix` was worse: it silently rewrote files mid-turn (deleting imports written before the body that uses them) and exited 0 with empty stderr, leaving Claude's in-memory copy stale. Running the gates at the **turn boundary** fixes both — nothing mutates while Claude is still authoring, and cross-file regressions are actually seen — at a cost of ~1.7s per turn (warm; `pytest -q` is ~1.3s of it).

## Continuous integration

`.github/workflows/ci.yml` (GitHub Actions) runs the **same four gates the hooks enforce locally** — `ruff format --check`, `ruff check`, `ty check`, `pytest` — plus `uv sync --locked` (fails on lockfile drift), across a **Python 3.12 + 3.13 matrix** (`fail-fast: false`) on push to `main`, every pull request, `workflow_call` (so `release.yml` can gate on it), and manual `workflow_dispatch`. Installs via `astral-sh/setup-uv` (cached). **Needs no secrets**: tests mock `DeepgramClient`, so CI never makes a real API call (upholds the PHI policy). Hardening: least-privilege (`permissions: contents: read`), both actions **SHA-pinned** (with `# vX.Y.Z` comments, kept fresh by `.github/dependabot.yml`), `persist-credentials: false` on checkout, a job `timeout-minutes: 10`, and a `concurrency` group that cancels superseded runs.

**The job id and the matrix values are a branch-protection contract, and this is the repo's highest-consequence silent-failure mode.** GitHub names an unnamed matrix job's check runs `<job-id> (<matrix value>)`, so `checks:` + `["3.12", "3.13"]` are the *sole* source of the `checks (3.12)` / `checks (3.13)` contexts the `main` ruleset requires. Rename the job, add a `name:` to it, drop a leg, or add a **second matrix dimension** (an `os:` leg renames every context to `checks (ubuntu-latest, 3.12)` — `tests/test_ci_workflow.py` asserts `set(matrix) == {"python-version"}` for exactly this reason), and a required context is never reported again — GitHub holds it **pending forever**, every PR becomes unmergeable, and `gh pr merge --auto` waits on something that will never arrive, with **no error surfaced anywhere**. Change the ruleset first. The matrix is also the only interpreter pin (there is no `.python-version`), so it is what verifies the `requires-python = ">=3.12"` floor. Everything in the file is load-bearing for a reason of this kind; a four-lens audit found nothing removable, so treat "tidying" it as a change to repo settings, not to YAML.

The workflow is itself guarded by `tests/test_ci_workflow.py`, which **parses it with PyYAML** and asserts structural invariants (gates run in real `run:` steps, the job id / matrix values / `fail-fast: false` are pinned, `workflow_call` stays available, every `uses:` is SHA-pinned, no `write` permission scope, `pull_request` not `pull_request_target`, no untrusted `github.event.*`/`head_ref`/`inputs.*` interpolation in a `run:` step).

## Release automation

`.github/workflows/release.yml` (GitHub Actions) cuts releases from a **version bump**, not a hand-pushed tag. Bump `[project].version` in `pyproject.toml` (keep it **static** and plain `X.Y.Z` — a `dynamic = ["version"]` would drift from the tag, and no `[tool.poetry]` table) and land it on `main`; the workflow reads the declared version, and if `vX.Y.Z` is not tagged yet it gates on CI, creates the tag, and publishes the Release with `--generate-notes`.

**One workflow does both halves, and that is the whole design.** GitHub will not start a workflow run from a ref created by the default `GITHUB_TOKEN` (the recursive-workflow guard), and **the guard is keyed on the token, not the transport** — a `POST /git/refs` is suppressed exactly as a `git push` would be. So the obvious split ("workflow A pushes the tag, workflow B fires on it") cannot work without minting a PAT or App token, in a repo that advertises needing no secrets. Doing both in one run needs no second identity, and the guard then works *for* the design: the tag this run creates cannot start a second run, which is what makes keeping the `v*` escape hatch safe from double-releasing. **The same rule runs forward**: the `release: published` event this run emits will not start an `on: release` workflow either, so anything that must happen on a release (a PyPI publish, say) belongs in the `release` job as another step — wired as its own workflow it would silently never run.

Three jobs: **`resolve`** (parses the version with stdlib `tomllib` — a grep would catch `requires-python` — validates it as a plain `X.Y.Z` before it becomes a git ref *and* a `$GITHUB_OUTPUT` line, and probes `GET /git/ref/tags/{tag}`, the **exact-match** endpoint; the older plural `git/refs/` prefix-matches, so `v0.1` would "find" `v0.10.0`); **`gate`** (`uses: ./.github/workflows/ci.yml`, skipped when there is nothing to release so an ordinary push does not run CI twice); **`release`** (creates the tag via an atomic `POST /git/refs` — `create || confirm-it-exists-now`, never a `PATCH`, so it can create a tag but never move one — then `gh release create … --generate-notes --verify-tag`). On the `v*` escape hatch, `resolve` additionally **refuses a pushed tag that disagrees with the declared version** (`exit 1`), so hand-tagging `v0.9.0` on a 0.8.1 tree stops there instead of publishing a Release that lies.

**Detection is level-triggered, never a diff**: it asks "is the declared version tagged yet?", not "did this push change it?". That is why there is no `paths:` filter — the property being bought is self-healing, so an evicted or half-dead run recovers on the next push. It also avoids `github.event.before` (all-zeros on a first push, dangling after a force-push) and `HEAD~1` (misses a bump that is not in the tip commit of a multi-commit push).

The **CI gate is not belt-and-braces**: the `main` ruleset requires `checks (3.12)`/`checks (3.13)` but does **not** require a pull request, and carries an always-bypass actor — so a direct push to `main` can skip CI, and the gate is the only thing between a red commit and a published Release. Do **not** add the reusable-call check runs to branch protection: they never run on `pull_request`, so every PR would hang and take the Dependabot `--auto` queue with it.

Least-privilege: top-level `contents: read` with `contents: write` confined to the single publishing job, and pointedly **no `pull-requests` scope** (it opens no PRs, so it can never hit the "GitHub Actions is not permitted to create or approve pull requests" policy); `concurrency` uses a constant group with `cancel-in-progress: false` (never abort a mid-publish run, and serialize a main push against a hand-pushed tag). Guarded by `tests/test_release_workflow.py`, whose `test_no_secrets_are_used` / `test_every_gh_token_is_the_default_token` are what keep the recursion reasoning above true.

**Known limits, stated rather than hidden.** A constant concurrency group keeps only one *pending* run, so three rapid pushes evict the middle one — detection self-heals on the next push, but bump one version per PR. Reverting to an already-released version does nothing; rollback means a forward bump. A hand-made **draft** Release for the target tag makes the publish step fail loudly rather than stomp it.

## Dependabot auto-merge

`.github/workflows/dependabot-auto-merge.yml` (GitHub Actions) lets the weekly **grouped** action-bump PR land itself: it enables GitHub's auto-merge (`gh pr merge --auto --merge`) so the PR merges only once the required CI checks pass. **Majors are excluded** (`if: steps.metadata.outputs.update-type != 'version-update:semver-major'`) — a major is where a breaking change hides (setup-uv v10.0.0 disabled the cache on `pull_request_target`/`workflow_run`/`release`), so those still get a human; `update-type` is the **highest** bump in the PR, so one major anywhere in the group keeps the whole PR manual.

**`pull_request_target` is load-bearing, not incidental**: a `pull_request` run triggered by Dependabot gets a **read-only `GITHUB_TOKEN` that a `permissions:` block cannot elevate**, and enabling auto-merge needs write. That trade is only sound because the job **never checks the PR out and executes nothing from it** — the single invariant `tests/test_automerge_workflow.py::test_never_checks_out_pull_request_code` exists to keep true; adding an `actions/checkout` here would hand a writable token to fork-controlled code. The job is gated on the `dependabot[bot]` actor **and** `github.repository` (so a fork can't auto-merge on its own copy), `dependabot/fetch-metadata` is SHA-pinned and by default fails unless the branch carries only Dependabot-authored commits, the PR URL flows through a `PR_URL` env var (no `${{ }}` shell interpolation), and it holds **exactly** `{contents: write, pull-requests: write}` in its own file — deliberately never merged into `ci.yml`/`release.yml`, which stay free of a `pull-requests` scope.

**Two repo settings are prerequisites**, and the workflow is inert (or unsafe) without both: **Allow auto-merge** must be enabled, and `main` needs a ruleset/branch protection making `checks (3.12)` + `checks (3.13)` **required status checks**. With no required checks there is nothing for `--auto` to wait on.

## Architecture

### Core — `nova/` (imports no streamlit)

- **`config.py`** — the single source of truth for constants: `MODEL` (`nova-3-medical`), `LANGUAGES` (8 English variants — Nova-3 Medical is English-only), `REDACT_GROUPS` ordered **PII-first** (`pii`/`phi`/`pci`/`numbers`; PHI labeled to flag that it strips clinical content), `DEFAULT_LANGUAGE`/`DEFAULT_SMART_FORMAT`/`DEFAULT_DICTATION`/`DEFAULT_MEASUREMENTS`/`DEFAULT_DIARIZE`, `MAX_KEYTERMS`/`MAX_UPLOADS`/`MAX_CONCURRENCY`/`MAX_FILE_SIZE` (200 MiB, pinned to match `.streamlit/config.toml`'s `[server].maxUploadSize = 200` — see Configuration), `AUDIO_EXTENSIONS`, and `has_audio_extension()`.
- **`transcribe.py`**:
  - `build_options(*, keyterms=None, language=None, smart_format=DEFAULT_SMART_FORMAT, dictation=DEFAULT_DICTATION, measurements=DEFAULT_MEASUREMENTS, diarize=DEFAULT_DIARIZE, redact=None)` — the kwargs dict for the Deepgram call; every parameter is keyword-only **and defaulted**, so a bare `build_options()` yields a valid default request (which is how `tests/test_transcribe.py` builds its baseline). `model` + `smart_format` are **always** sent; off-by-default features are sent only when enabled — `diarize`/`measurements`, and `dictation` (which also forces `punctuate=True`) — plus `keyterm`/`language` only when truthy. `redact` (typed as a single `str` by the SDK) goes through `request_options["additional_query_parameters"]={"redact":[...]}`, which is omitted entirely when unset.
  - `ItemResult` dataclass `{index, label, response, error}` — `error` is `str(exc)` with no prefix; the calling adapter owns presentation.
  - `transcribe_batch(api_key, items, method, *, options, client_cls=None, as_completed_fn=None, max_concurrency=MAX_CONCURRENCY, on_progress=None)` — one shared client per batch via `ThreadPoolExecutor`; merges `options` onto each item; captures per-item exceptions (one failure never aborts the batch); sorts results back into input order. **`client_cls`/`as_completed_fn` default to `None` and resolve to this module's globals at *call time*** (not def-time) so `tests/test_transcribe.py` can `patch("nova.transcribe.DeepgramClient")` while the in-process UI wrapper injects its own globals as seams. `on_progress(done, total)` fires once per completion.
- **`results.py`** — getattr-guarded response walkers (no `st.*`): `first_alternative`, `transcript_text` (→ `.transcript` or `None`), and `diarized_segments` (groups `alternatives[0].words` into consecutive `(speaker, text)` runs, gated on an integer `words[0].speaker`; `text` uses `punctuated_word` falling back to `word`). **Speaker values from the walkers stay Deepgram's native 0-based ints; the shared display helpers are `speaker_label` (the single home of the `+1` offset → `int | None`) and `word_token` (`punctuated_word` → `word`). `speaker_label` is reused by both the Streamlit renderer and the SRT export; `word_token` by the SRT export (and internally by `diarized_segments`).**
- **`subtitles.py`** — `to_srt(response)` builds SRT subtitle text from `alternatives[0].words` (via `first_alternative`), grouping words into cues on a speaker change / sentence-ending token / `MAX_CUE_WORDS` (12) / `MAX_CUE_SECONDS` (6.0) cap, and skipping words without numeric `start`/`end`. Diarized cues carry a **1-based** `Speaker N:` prefix via the shared `nova.results.speaker_label`; a results-less (or no-timed-cues) response yields `""`. Streamlit-free and never calls `model_dump_json`, so it's unit-tested directly and safe to import at module load.

### Streamlit UI — `streamlit_app.py`

Re-imports the core constants under their old underscore names (`_LANGUAGES`, `_REDACT_GROUPS`, `_AUDIO_EXTENSIONS`, the `DEFAULT_*`/`MAX_*` names, `has_audio_extension`, `build_options`, `transcribe_batch`), aliases the walkers (`from nova.results import transcript_text as _transcript_text, diarized_segments as _diarized_segments, first_alternative as _first_alternative, speaker_label as _speaker_label`), and imports the SRT builder (`from nova.subtitles import to_srt as _to_srt`) — preserving every existing test patch point. (`first_alternative` backs the per-result Confidence metric.)

Visual theming lives in `.streamlit/config.toml` — a **single `[theme]` table** carrying the **Nord** palette (`base = "dark"`, `primaryColor = "#5E81AC"`, Polar Night surfaces `#2E3440`/`#3B4252`, Snow Storm text `#ECEFF4`), plus a `[theme.sidebar]` table lifting the Features form one step to nord1. **There is deliberately no `[theme.light]`/`[theme.dark]`**: Streamlit exposes the Settings-menu Light/Dark/System switcher *only* when both mode tables exist, so one table locks the app to Nord and removes the toggle — re-adding either restores it. The semantic color keys (`blueColor`…`grayColor`, Frost + Aurora) back the diarized speaker highlights, and all six `_SPEAKER_COLORS` names (`blue`/`green`/`violet`/`orange`/`red`/`gray`) must stay defined. **`primaryColor` is deliberately nord10 `#5E81AC`, not Nord's canonical nord8 `#88C0D0`.** It is the background of the `type="primary"` Run submit button (`streamlit_app.py`), and Streamlit **hardcodes that label white** — there is no `primaryTextColor` among the 277 `theme.*` options, and the frontend runs no luminance math, so nothing auto-corrects it. Measured in-browser: white on `#88C0D0` is **2.00:1**, on `#5E81AC` it is **4.03:1**. The upstream Nord template ships `#88C0D0` because it assumes no filled primary button. Restore nord8 only alongside demoting that button to `type="secondary"`. Typography loads **Inter** (`font`, UI/headings) and **JetBrains Mono** (`codeFont`, JSON view) **self-hosted** from `static/` (served at `app/static/*` via `[server].enableStaticServing`) with a system-stack fallback — the upstream Nord template pulls both from Google Fonts and that is deliberately not used, so no third-party font CDN is contacted; `baseFontSize = 14` and the six-entry `headingFontSizes` tame Streamlit's oversized defaults. Pure config, so it never touches the test suite. `st.set_page_config(page_title=…, page_icon="🩺", layout="wide")` is the first Streamlit command.

1. Resolves `DEEPGRAM_API_KEY` — environment first (`.env` via python-dotenv), then `_secret_api_key()`, a guarded `st.secrets` read for deployed hosts with no `.env`; prompts inline if both come up empty.
2. `_transcribe_batch(api_key, items, method, **opts)` — a thin UI adapter over `nova.transcribe.transcribe_batch`, where `**opts` is the `_feature_opts()` dict (`keyterms`/`language`/`smart_format`/`dictation`/`measurements`/`diarize`/`redact`) forwarded straight into `build_options`. It:
   - builds the playback `sources` up front — `_playback_source` keeps URLs/small audio but stores `None` for upload bytes over `MAX_PLAYBACK_BYTES` (25 MB);
   - drives a live `st.status` region (nested `st.progress` bar + label updated via an `on_progress` callback, auto-collapsed to `state="complete"` on finish);
   - renders one `st.error` per failed item (these land *after* the batch finishes rather than interleaved — no test pins the timing);
   - **unconditionally** writes `st.session_state["responses"]` and the parallel `["audio_sources"]`, so a fully-failed run clears stale results;
   - fires a one-shot completion `st.toast` (`_completion_toast` — success / partial / all-failed);
   - passes the module-global `DeepgramClient`/`as_completed` as seams.

   A `None` source renders a `PLAYBACK_TOO_LARGE` caption instead of a player — and unlike the oversize-upload error, that caption **hardcodes its own "25 MB"** rather than deriving it, so changing the constant alone leaves the caption lying.
3. `_process_inputs` / `_process_urls` — wrap `_transcribe_batch` for uploads / remote URLs.
4. `_feature_opts()` — reads the Features control values (the **sidebar** form, not a tab) from `st.session_state` (by widget `key`, falling back to the `DEFAULT_*` constants — except `keyterms`/`redact`, which fall back to `[]`).
5. `_run(api_key, uploaded_files, recording, url_text)` — the Run handler: `st.info`s when more than one input is populated, then validates and transcribes the highest-priority input, **Upload → Record → URL** (file count/size; recording duration via a guarded `wave.open`; URL protocol/`has_audio_extension`), via `_process_inputs`/`_process_urls` with `**_feature_opts()`.
6. Renderers:
   - `_display_transcript` — a `_display_metrics` row of `st.metric` cards (Duration + alternative-level Confidence, via `_result_metrics`, rendered only when available), then: with diarization, one Markdown-escaped per-speaker line **color-highlighted** by speaker index via native `:{color}-background[**Speaker N:**]` directives from `_SPEAKER_COLORS`, **1-based** display; otherwise the flat escaped transcript, or `st.caption(NO_TRANSCRIPT)`.
   - `_display_json` — `st.json(response.model_dump_json())`, deliberately minimal: no markdown/expander/download.
   - `_transcript_download` — Transcript-tab downloads in one `st.container(horizontal=True)` toolbar row: all transcripts as `.txt` via a **deferred** zero-arg `data` callable over `_plain_transcript` (blob assembled on click, not every fragment rerun), plus — for a single result that yields timed cues — an `.srt` export via `_to_srt`.
   - `_output_panel` — pinned players + fixed-height container or placeholder; `None` source → `PLAYBACK_TOO_LARGE` caption.
   - `_display_audio` (MIME from extension via `_AUDIO_MIME`, default wav; URL passed through) and `_escape_markdown`.

   Per-speaker highlighting uses native Markdown color directives (no raw HTML/CSS), so it stays test-safe. Status callouts (`st.error`/`st.warning`/`st.info`) and the completion `st.toast` carry Material Symbol icons (`:material/…:`).
7. Layout — `layout="wide"`, a `st.caption` subtitle below the title, then two zones:
   - **Sidebar (`st.sidebar`)** — the **Features** controls (canonical home for app-level settings, freeing the full main width for output): a `:material/tune:` caption over an `st.form("features", border=False)` so edits don't rerun until submit — Language, Keyterm Prompting, Smart Format, Diarize, Dictation, Measurements, Redact — closed by a full-width `st.form_submit_button("Run", icon=":material/graphic_eq:", width="stretch")` carrying a `help=` hint when disabled.
   - **Main area** — a side-by-side `st.columns(INPUT_OUTPUT_RATIO)` split (`(2, 3)`), which stacks inputs-first at ≤640px:
     - **left** — the Material-icon'd audio input tabs (Upload ≤100 files/200 MB each; Record `st.audio_input` ≤10 min; URL HTTP/HTTPS ≤100). Run feedback (validation callouts, the `st.status` progress region, per-item errors) renders here too (`with input_col: _run(…)`), so it never pushes the output's top edge down.
     - **right** — the **Transcript**/**JSON** tabs (also icon'd) rendered by `_render_output` (an `@st.fragment`, so switching tabs reruns only that panel) over `_output_panel`. `st.tabs(…, on_change="rerun")` plus an `if tab.open is not False:` guard skips the hidden tab's body at runtime — notably the JSON tab's per-response `model_dump_json()` (inert under the test mock, where `.open` is truthy).

     `OUTPUT_HEIGHT` (480) is **measured, not arbitrary**: it is the tallest panel whose bottom still clears the fold of a ~840px-tall viewport (1080p minus browser chrome) in the tallest case — a single result, with the download row and pinned player above it (panel spans y≈334–814). Streamlit has no viewport-relative height (`height="stretch"` needs a bounded parent), so raising it reintroduces a page scroll nested around the panel's own scroll. The empty-state placeholder copy is deliberately direction-free ("Select audio, then…") because the inputs sit *beside* the output on desktop but *above* it once stacked.

## Configuration

The only env var is `DEEPGRAM_API_KEY` (server-side only), loaded from `.env` (gitignored; see `.env.example`) via python-dotenv, with `st.secrets` as a deployment fallback (`_secret_api_key()`) for hosts that have no `.env` — Streamlit Community Cloud writes dashboard secrets to a `secrets.toml` instead; the UI still prompts inline if both come up empty. **That read must stay guarded**: `st.secrets` raises `StreamlitSecretNotFoundError` on *every* access — `.get()` and `in` included — when no secrets file exists, which is the normal local setup here, so an unguarded probe would crash the app on import. Touching `st.secrets` at all is also the only thing that mirrors top-level secrets into `os.environ`, which is why an environment-only read comes up empty on Cloud even when the secret is configured.

**Secrets are guarded in both directions**, because `block-secrets.sh` structurally cannot cover reads — a PreToolUse hook matching `Edit|Write|MultiEdit` never sees a `Read`. The **write** side is the hook; the **read** side is a `permissions.deny` block in the same tracked `.claude/settings.json`, denying `Read` on `.env`, `.env.*`, `.envrc`, `.envrc.*` **at the repo root only** (those rules are `./`-anchored, and `*` does not cross a `/`), plus `secrets.toml` / `.secrets.toml` at the root **and at any depth** (`./**/`). That asymmetry is deliberate but worth knowing before you rely on it: the write hook matches `*.env`/`*.envrc` at **any** depth, so a nested `config/.env.local` is unwritable yet still **readable**. Add `./**/` variants before putting a real env file in a subdirectory.

Two consequences worth knowing before editing those rules:

- **`.env.example` is collateral, deliberately.** Deny rules beat `allow` rules unconditionally, and the matcher supports no negation (neither extglob `!(example)` nor a `[!e]` class — both are accepted silently and match nothing, which is *worse* than an error). So `Read(./.env.*)` also blocks the tracked template, and since `Edit` requires a prior `Read`, Claude can no longer maintain `.env.example` — you edit it yourself. This is the fail-closed choice: enumerating `.env.local` / `.env.production` / … instead would leave an unanticipated `.env.staging` readable, which is the same hole class as the `.envrc.local` gap above. A loud block on a tracked template beats a silent miss on a real secret.
- **Permission rules are per-tool, so `cat .env` via Bash is still unguarded.** Closing that would mean parsing shell, which is not worth attempting; treat it as a known limit rather than a rule to add.

The Streamlit UI's visual theme is non-secret config in `.streamlit/config.toml` (tracked); secrets (`.env`/`.env.*`, `.streamlit/secrets.toml`) are gitignored. The theme self-hosts Inter / JetBrains Mono as WOFF2 in `static/` (served at `app/static/*` via `[server].enableStaticServing`), so **no request leaves the app to a third-party font CDN**; faces fall back to the system sans/mono stack if they fail to load. `[browser].gatherUsageStats = false` closes the other outbound path: Streamlit's anonymous usage telemetry **defaults to `true`** and posts to `webhooks.fivetran.com` (5 requests per page load, measured). It carries usage metrics rather than transcript content, but an unaudited third-party beacon from a clinical-transcription page is not worth defending under the PHI policy — with both set, the only traffic the app originates is the Deepgram API call itself. See `static/FONTS.md` for attribution (both are SIL OFL 1.1). The `[server]` block also pins `maxUploadSize = 200` (MB) — the effective per-file upload cap — which must stay in sync with `nova.config.MAX_FILE_SIZE`: Streamlit silently caps uploads at its 200 MB default, so a larger app-side guard would be unreachable (as the former 2 GiB cap was). The oversize `st.error` derives its size from `MAX_FILE_SIZE` (`f"Skipped (exceeds {MAX_FILE_SIZE // (1024 * 1024)} MB): …"`), keeping the limit in one place.

## Testing

Tests mock `DeepgramClient` — no real API calls. **Two mock points, by design:**

- **`streamlit_app.DeepgramClient`** — UI tests (the `_transcribe_batch` wrapper passes this module global as a seam).
- **`nova.transcribe.DeepgramClient`** — core tests (the core resolves its `None`-default seam at call time, so `test_transcribe.py` patches the module global directly).

The five **guard** tests below (`test_ci_workflow`, `test_release_workflow`, `test_automerge_workflow`, `test_dependabot`, `test_license`) are config-only and have no API surface: they exist because YAML / `LICENSE` / `pyproject` metadata is invisible to `ruff`/`ty`/`pytest`, which only read `.py`. That is why they are real tests, not clutter — do not delete them as "not testing code".

- `conftest.py` (root) — adds repo root to `sys.path` so tests can `import streamlit_app`, `nova`.
- `tests/conftest.py` — `mock_deepgram_cls` (patches `streamlit_app.DeepgramClient`), `mock_st`.

Cover `block-secrets.sh` (PreToolUse: deny `.env`/`.env.*`/`secrets.toml`/`.envrc.*` with exit 2 — case-insensitively — allow `.env.example`/source/docs, no-op on missing path, and **fail closed both ways**: `jq` missing *and* unparseable event JSON, the latter via a `run_hook_raw` helper that feeds non-JSON stdin) and `gates.sh` (Stop: only the two short-circuit branches — the `stop_hook_active` loop guard, and the fail-**open** no-toolchain preflight that is the mirror image of block-secrets' fail-closed. The real-run path is deliberately untested here: it shells out to `uv run pytest`, which would re-collect this module → recursion).
- `tests/test_ci_workflow.py` — **guard** over `.github/workflows/ci.yml`: **parses the workflow with PyYAML** and asserts it is valid, exposes a `checks` job whose `run:` steps wire all four local hook gates plus `uv sync --locked`, **pins the required-status-check contract** (job id, no `name:` on the job, `matrix.python-version == ["3.12","3.13"]`, `fail-fast: false`), keeps `workflow_call` available for `release.yml`'s gate, SHA-pins every `uses:`, stays least-privilege, triggers on `pull_request` (never `pull_request_target`), and interpolates nothing untrusted into a `run:` step. The YAML 1.1 `on:`→`True` key quirk is handled explicitly.
- `tests/test_release_workflow.py` — **guard** over the bump-triggered `release.yml`: **parses it with PyYAML** and pins that it
  - triggers on a `main` push plus the `v*` escape hatch and a no-input `workflow_dispatch` — never `pull_request`/`pull_request_target`, and with **no `paths:` filter**, which would make detection edge-triggered;
  - confines `write` to the publishing job, with no `pull-requests` scope anywhere;
  - is **gated on `ci.yml`**, with both `gate`/`release` skipped when there is nothing to release;
  - reads the version with `tomllib` and validates it as `X.Y.Z`;
  - creates the tag through the REST API (**no `git push`/`git tag`**; comment lines are stripped before scanning so the prose explaining the rule does not trip it) and never `PATCH`es it;
  - publishes with `--generate-notes --verify-tag` behind the `isDraft` guard;
  - **uses no secrets, and every `GH_TOKEN` is `${{ github.token }}`** — the invariant the whole one-workflow design rests on;
  - cross-checks that `pyproject`'s `[project].version` satisfies the same shape the workflow enforces, so a bad bump fails in the Stop hook rather than reddening a post-merge release run.
- `tests/test_automerge_workflow.py` — **guard** over `dependabot-auto-merge.yml`: **parses it with PyYAML** and pins that it triggers **only** on `pull_request_target`, **never checks out or fetches the PR's code** (no `checkout` in a `uses:`, no `git checkout|fetch|clone`/`gh pr checkout` in a `run:` — the invariant that makes a writable token on a PR event safe), holds **exactly** `{contents: write, pull-requests: write}`, gates the job on both the `dependabot[bot]` actor and `github.repository`, excludes `version-update:semver-major` from the merge step, queues via `--auto` (not an immediate merge), never cancels mid-merge, sets a job timeout, SHA-pins every `uses:`, and interpolates no untrusted `github.event.*`/`head_ref`/`inputs.*` into a `run:` step.
- `tests/test_dependabot.py` — **guard** over `.github/dependabot.yml`: **parses it with PyYAML** and pins the invariants that keep the Actions SHA-pins from rotting — schema `version: 2`, and a `github-actions` update **rooted at `/`** (one root entry monitors every workflow under `.github/workflows/`, so `ci.yml`'s pinned actions are covered without a per-workflow entry; `release.yml` shells out to the preinstalled `gh` CLI and pins nothing) on a `schedule.interval`.
- `tests/test_license.py` — **guard** over the MIT license declaration: asserts the `LICENSE` file exists and carries the MIT markers (title / permission grant / `AS IS` disclaimer) plus a well-formed `Copyright (c) <year|range> <holder>` line, that `pyproject.toml` declares the PEP 639 SPDX `license = "MIT"` with every `license-files` entry resolving to a real file, and that the README names and links it. **Parses `pyproject` with `tomllib`** (stdlib), so equality with the plain string rejects the legacy `license = {text = "MIT"}` table. Cross-source agreement is the point: requiring MIT in **both** the `LICENSE` body and the SPDX id — and tying the `LICENSE` copyright holder to `[project].authors` — means swapping or renaming one source without the others trips a check.

## Dependencies

Managed by uv via `pyproject.toml` + `uv.lock`. **Every dependency is pinned exactly (`==`)**, runtime and dev alike, with dev deps in a PEP 735 `[dependency-groups] dev` table (so a plain `uv sync` installs them). `uv add` writes a `>=` range by default — rewrite it to `==` and re-run `uv lock`, or the pin convention and CI's `uv sync --locked` drift apart.

Runtime: **deepgram-sdk** (v7), **streamlit**, **python-dotenv**

Dev: **ruff**, **ty**, **pytest**, **PyYAML** (used by the config-guard tests — `tests/test_ci_workflow.py`, `tests/test_release_workflow.py`, `tests/test_automerge_workflow.py`, `tests/test_dependabot.py` — to parse the workflow / Dependabot YAML), **watchdog** (lets `streamlit run` use native file-system events for hot-reload instead of polling; dev-only, so deployed hosts don't need it)

Ruff lint config: `[tool.ruff.lint]` selects `E`/`F`/`I`/`UP`/`B` and ignores `E501` (line length is formatter-driven); `combine-as-imports = true` sits in the **`[tool.ruff.lint.isort]`** sub-table (keeps the UI's aliased re-exports in one block). The sub-table is required, not stylistic — `combine-as-imports` is an isort setting, and under `[tool.ruff.lint]` it is an unknown field that makes ruff refuse to load the config at all, failing **both** the `ruff format` and `ruff check` gates.

**deepgram-sdk** notes (v7, project pins `7.10.0`): options are keyword args (not `PrerecordedOptions`), API key passed explicitly to `DeepgramClient(api_key=...)`, responses are Pydantic models. The namespaced client path is `client.listen.v1.media.transcribe_file(request=<bytes>)` / `transcribe_url(url=<str>)`; most options (`model`, `smart_format`, `keyterm`, `language`, `dictation`, `measurements`, `diarize`, `punctuate`) are typed keyword args. `redact` is typed as a single `str`, so multiple redaction groups go through `request_options={"additional_query_parameters": {"redact": [...]}}` (repeated query params).

- **Response-type union**: the transcribe methods are typed to return `ListenV1Response | ListenV1AcceptedResponse`. The UI only ever receives `ListenV1Response` (which has `results`) because it never passes `callback=`; `ListenV1AcceptedResponse` (callback/async mode) carries only `request_id` and no `results`. `nova.results.first_alternative` guards the `.results` access so the walkers degrade gracefully if that ever changes.
- **Version**: pinned to `deepgram-sdk==7.10.0` (requires Python 3.10+, satisfied by this app's 3.12 floor). The pre-recorded REST surface and the response-type union are identical from v5 through v7; the breaking changes across those majors were confined to the websocket/streaming/TTS/agent APIs this app does not use (see [`docs/Migrating-v5-to-v6.md`](https://github.com/deepgram/deepgram-python-sdk/blob/main/docs/Migrating-v5-to-v6.md) / [`docs/Migrating-v6-to-v7.md`](https://github.com/deepgram/deepgram-python-sdk/blob/main/docs/Migrating-v6-to-v7.md) in the deepgram-python-sdk repo).
